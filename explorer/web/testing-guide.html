项目文件夹：哪些要用，哪些只是背景

项目 README ↗
目录用途测试时怎么使用
data/ · 数据入口版本化数据集，包括输入、答案、证明和来源快照。按本页逐文件说明使用，不将整个目录交给模型。
docs/ · 研究文档文献调研、场景、指标、协议，以及 report/ 报告归档。理解定义与评分边界；不是题面材料。参考报告不作为设计决策或标准答案来源。
src/ · 构建与校验数据构建器和结构检查。测试已交付文件通常无需重建。重建会改写数据，必须另行固定新版本。
evaluation/ · 评测实现位置预留配置、评分与错误归因实现。当前没有正式评分器；不能把空目录理解成已交付可执行评分流程。
artifacts/ · 保留的实验产物正式运行记录、结果和分析。建议按独立运行编号保存输入快照、输出与评分；不要覆盖原始数据。
workspace/ · 临时工作输出检索、程序检查、浏览器截图与临时日志。这些是构建/系统检查，不是模型成绩。需要保留的实验结果应整理到正式产物位置。
explorer/ · 可视化系统题目、标签、合法证明、资料和潜在干扰审查。页面和 bundle API 含 gold，仅用于人工审查，不可把网页或完整 API 响应作为模型输入。
.github/ · 仓库协作配置已有仓库协作设置。不属于 benchmark 题面或模型评测标注。

目录链接指向对应说明；没有独立说明的目录链接到项目 README。本页不要求测试组修改构建流程或系统结构。

DATASET 01

pilot_literature_history_v0

数据集完整说明 ↗

目录为 data/pilot_literature_history_v0/。版本 pilot-v0.1：10 个设计组合、20 个题目家族、128 条主任务，文学和历史各 64 条，覆盖 27 个实际场景单元；另有 58 条独立节点诊断。

98可作答记录
8多解释歧义
22材料不足
58Oracle 节点题另列

128 条包含共享家族的变体，不能当成 128 道独立原题。当前全部属于开发候选集，没有独立人工复核、正式测试划分或模型实跑结果。

数据集文件由谁/在哪使用具体用途能否直接送入模型
inputs.jsonl主任务模型调用128 行清洁输入。每行包含 id、instruction、question、documents、output_contract。可以，每行作为一题；保留统一指令、材料 ID 和材料顺序。
oracle_inputs.jsonl独立节点模型调用58 行诊断输入，题面已给正确上游，用于 Oracle-CS。可以，另开诊断运行；不接续主任务对话。
benchmark.jsonl评分、分组与错误分析128 行完整标注：标准答案、状态、证明 DAG、场景、家族、配对差异、映射及设计预期。不可以整行送入，含 gold。按 id 与主任务输出关联，只在评测侧使用。
oracle_gold.jsonl节点诊断评分58 行节点答案、母题、家族、正确上游与支持材料，与节点输入按 id 对齐。不可以，尤其不能把节点答案加入提示。
seeds.json构建审查与溯源20 个家族的原型关系图、问句、风险和来源组；不是额外测试题。不可以，可能透露路径、答案和原型设置。
sources.json资料核验4 页原文的摘录、定位、修订链接和许可。反事实只保留改写前锚点。不可以当额外材料补入，否则会改变证据条件或覆盖反事实世界。
combinations.json设计组合核验构题前的计划配方。逐题场景以完整标注的 scenario_ids 为准。不可以，计划标签不属于题面，也不能机械套到所有变体。
题目审阅册.md人工查题可读的问句、主要材料、答案、完整证明和变体列表。不可以，包含标准答案和证明。
README.md协议准备来源、数据字段、构造控制、局限、重建和预备评分口径。不是模型题面；先理解协议，再运行清洁输入。
输入边界模型只接收对应清洁输入文件中的当前题。不要附上答案、标签、实体映射、原型链、删除证据、来源全文或先前变体答案。

主任务：建议按这个顺序运行

128 条 / 独立题次
  1. 先固定数据快照。记录数据集 ID、版本、所用输入与 gold 文件 SHA-256。运行期间不重建、不编辑文件；不同模型用同一快照。
  2. 逐行读取 主任务输入。保留 instruction、question、documents 的 ID/文字/顺序以及 output_contract；id 用于关联输出，可以作为不透明题号。无材料题的 documents=[] 必须原样保留。
  3. 每一题使用独立上下文。不把同一家族各变体串成同一对话；不从上一题继承事实、答案或反事实更正。主测试按给定材料闭合运行，不增加联网、检索或其他外部知识工具。
  4. 保留回答与证据记录。按 output_contract 要求答案、状态、引用材料 ID 和简短关系/操作步骤；不要求模型揭示隐藏思维链。原始回答即使无法解析也要保存。
  5. 调用侧与评分侧分开。生成完成后，按 id 关联 完整标注。不要先读 gold 形成提示，或让模型看到可视化详情页面。
  6. 先核对完整性，再统计成绩。记录计划题数、已提交题数、有效响应数、解析失败、超时和失败重试；不静默删除失败样本或只保留答对的重试。

一次调用应包含什么

题号：当前记录的 id
统一指令：instruction
问题：question
材料：按 documents 原顺序逐份呈现 [材料 id] + text
输出要求：output_contract

评分侧保留：gold、facts、query、scenario_ids、family_id、
control_id、challenge_id、paired_changes、entity_mapping 等；
这些不进入模型提示。

这里规定信息边界，不指定某家模型的 API、角色消息格式或 SDK。若使用不同消息包装，需事先固定模板、保留全部题面并记录模板版本；不能对某个模型追加提示。

模型设置须可追溯

记录实际模型/端点版本、运行日期、提示模板、温度与采样参数、输出长度限制、随机种子（若支持）、工具权限、调用预算和重试规则。相同设置不保证服务端绝对确定；需要重复运行时事先固定次数，分别报告，不挑最好的一次。

背景档按字符构造，没有针对所有模型做 token 匹配。先检查每题是否完整进入上下文；输入截断必须单独标记，不能把截断导致缺证据全部算成推理错误。

独立节点诊断：Oracle-CS 怎么跑

58 条 / 基础查找节点

使用 节点输入 新开一组独立调用；这些问题已经把正确上游写入题面。保持相同模型设置，不携带主任务作答记录。

输出按节点 id 关联 节点标注，再用 parent_id、family_id、node_id 汇回母题。本批 Oracle-CS 分母为 58 条计划节点题，解析/运行失败规则提前固定并单列；不能靠删除失败来缩小分母。

Oracle-CS = 正确完成的独立节点题数 / 58
本批覆盖：基础对照中的关系查找节点
尚未覆盖：比较、成员过滤、求和、溯因等全部部件
不能替代普通回答里某一步写对，不等于在正确上游条件下独立完成节点题，也不能冒称 Oracle-CS。主任务和节点诊断数量分开报告。

评分与配对：先冻结规则，再批量跑

多步骤评判协议 ↗

当前交付有输入、gold 和参考证明，尚无正式可执行评分器。先固定中文答案规范化、解释映射、支持与操作匹配、拒答/澄清、失败响应和重试规则，做小批核对，再批量比较；不要拿浏览器或构建器测试通过当模型得分。

指标/统计本批怎么用容易混淆的边界
答案与状态全体128条报告状态行为；98条可答、8条歧义、22条不足分别统计。标准答案“不确定”的规则判断仍为 answerable，logical_truth=unknown；不同于缺材料的 insufficient。
Strict SR在98条可答题中，答案正确且交出一条完整合法证明才通过；提前固定失败响应计法。gold.proofs 是多条完整参考图，不能从不同路径挑有利节点拼接。歧义/不足合规率另报。
Path-CFS按可观察的短证明检查局部合法性与上游依赖；以一个完整匹配参考图确定节点分母。只答末端不能缩小分母；生成的证明不是模型内部思考，也不是原论文的执行流水线观测。
保持型配对按照实际配对 ID 比较添加背景、重排、删除无关项等条件；报告两题均通过率及条件失效率。条件失效率的分母为基础题通过的有效配对数，分母为0记不可计算。
改变型配对内部桥改接、正反方向、换起点、换馆年等按各自 gold 检查应有变化。不能用“答案是否与基础题相同”评分。匿名/陌生名比较先按 entity_mapping 反向对应。
歧义与缺证据歧义检查解释—答案映射或有效澄清；不足检查证据限定下的合理拒答。有效澄清的计法需事先单列；删一处重复支持仍可答，删全部支持才不足。不能对照单一句子机械评分。

用于分组与配对的字段

family_id 连接同一母题全部变体；control_id/challenge_id 给基础与组合记录；paired_changes.parent_id 给实际比较对象及新增/删除/改写。不要只靠题号顺序或 variant 名称猜配对。

scenario_ids 是逐题实际场景；combination_id 回溯先行配方；domain、source_cluster_id、证明深度与命名方式用于分组。场景非互斥，场景样本数相加会重复计数。

汇报时必须分开

  • 记录数、家族数、有效配对数、节点题数；先呈现家族的各条件，再汇总场景/组合。
  • 答对但证明错、证据或角色错、加工操作错、歧义/不足行为错、运行/解析失败。
  • 绝对成绩、保持型稳定性、改变型更新响应、无材料证据约束和 Oracle 节点能力。
  • 本批共享来源和模板，全部是开发候选；没有正式独立测试划分，source_cluster_id 也不等于已完成全局防泄漏分组。
  • 匿名和自然名称的分数差包含表达、分词与可读性差异，不能直接解释为背景知识干扰的因果效应。

B 组结果记录与核对清单

保留原始输出

建议按独立运行编号在 artifacts/ 对应实验位置 保存结果。以下是建议记录项，不冒称已有冻结的结果 schema 或自动评分脚本。

运行配置与快照

数据集/版本、输入与gold散列、模型与设置、模板、日期、上下文限制、重试预算、计划与完成数量。

逐题原始与解析结果

run_id、task_type（主任务/节点）、id、原始回答、解析答案/状态/证据/步骤、调用状态与尝试次数。超时、空输出、截断和解析失败也保留。

评分与分组分析

评分规则/版本、逐题结果、匹配的完整证明、有效配对、家族与实际场景、失败类型及样例引用。修改评分规则时保留旧版本并重新一致评分。

  • ✓ 主调用只使用主任务清洁输入；节点调用只使用节点清洁输入。
  • ✓ 标准答案、证明、标签与原型资料未泄漏进提示；无材料条件未被补齐。
  • ✓ 家族变体在独立上下文运行，设置和输入快照一致。
  • ✓ 128条主任务与58条节点诊断分开记账，失败与重试有完整记录。
  • ✓ 多证明、规则未知、歧义、删桥、反事实和改名使用对应口径。
  • ✓ 不覆盖数据集，不把原型/浏览器检查或设计预期写成模型实测。
