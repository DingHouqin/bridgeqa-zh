## 2. E1：数据质量先行

保留全部候选的接收/修订/拒绝状态，人工复核来源、必要依赖、唯一性、时间/身份限定及替代路径。自动校验主要负责结构与不变量。

首轮合格率分母为全部接受审核的候选。拒绝原因允许多标签，需说明数量可能重复；最终种子数按独立种子计，另外报告共享来源簇数量。来源审核耗时、题目修订和攻击审核分别记录。

首次 10–12 个种子的试运行只用于校准与预算估计，不直接宣称整个正式题库达到该质量水平。

## 3. E2/E4：共用主实验

1. 冻结隐藏输入、gold、split/source_cluster、模型、提示、解析、解码与资源上限。
2. 检查 control/attack 的 gold、问题、文档顺序/数量、位置与长度差；人工确认没有新合法答案。
3. B0/B1 对相同输入独立答题，新会话、无跨题答案缓存；记录实际输入/输出 token、调用、耗时和失败。
4. 用相同规则分别评分；Strict SR 等新增指标实现及核验后才能填正式结果。
5. 按种子聚合、按攻击分别报告；共享来源组件时使用来源簇，不能把全部变体当独立 N。

优先主表：系统 × 条件（普通/主攻击）。跳数、辅助机制与中文困难标签作有限分层，四跳小组与攻击位置作描述。C0 可帮助诊断，但上下文长度不同，不据此直接估计证据选择的因果效果。

报告数值、分子/分母、数据规模与实际成本。若计算置信区间，使用预先约定的配对簇重采样；尚未实现时不能填假区间。小样本未见明显差异，不等于证明两个方法等效。

## 4. E3：诊断不混入正常主榜

- 对正式输出检查 Answer EM 与 Strict SR 的四种组合，重点核验“答案对、证明错”样例。
- Path-CFS 和首次错误仅说明提交证明；归类实体、关系/时间、证据、断链或格式失败。
- 在预选约 12 道三跳题上，为每跳准备单跳子问题及正确上游输入，保留候选干扰，独立运行 Oracle-CS。
- Oracle-CS 子集在观察隐藏结果之前按覆盖原则选定。另可对全量首次失败作 oracle-prefix 个案诊断，此时清楚注明是条件化选择，不能外推为全量恢复率。
- 干预 gold 不进入 B 组后续隐藏优化；C0、单跳、正确前缀结果分别报告，不并入正常准确率。

答案正确但 Strict SR 失败应根据真实输出核查；不用自由 CoT 文风替代证据判定。若需要人工核验全部这类案例，报告实际案例数量与审核状态。

## 5. E5：可选构题流程比较

复用试运行的事实包，比较 A：普通自然语言构题提示，B：Source Schema 与结构化生成约束。两种流程使用相同已核验事实、能力目标、候选数量、模型 revision、解码设置及输出格式，记录提示和实际 token。比较对象是整个流程，不把额外约束的效果声称为纯 JSON 格式效果。

每个事实包在两种流程下分别生成候选。隐藏生成方法标识后以同一准入标准审核，平衡顺序/审核者，记录审核者是否已熟悉该事实包。所有拒绝、修订和复审耗时计入，不只计算通过题的首次阅读时间。

```text
首轮合格率 = 首轮无需修订的合格候选 / 全部候选
流程运行人工分钟/最终合格题 = 审核+修订+复审总分钟 / 最终合格题数
包含准备成本的人力/题 = (准备+审核+修订+复审总分钟) / 最终合格题数
```

事实来源核验等共同成本也要记录，比较时说明是否共用；最终合格数为 0 时每题成本不可计算。若给扩容量下的成本摊销，注明它是预算推算。小试运行只能形成探索性证据，生成合格率不等于 LLM judge 准确率。

## 6. 验收和可用材料

- 每项贡献使用 [证据登记表](../../reports/contribution-evidence.template.csv) 保存状态与真实材料路径。
- 所有结果关联运行 manifest、gold/数据哈希、评分版本；状态从 planned 升级必须有实际材料。
- 公开仓库只保存计划、模板、允许公开的开发例子和汇总；隐藏逐题审核、gold、预测与明细在私有目录。
- 期中可以展示已实现的最小指标；期末主张必须与实际评分器能力一致。
- 记录局限与负结果，保留拒绝题日志；不以特定模型失败作为题目接收条件。
