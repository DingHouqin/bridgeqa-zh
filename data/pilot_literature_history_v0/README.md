# 文学与历史多跳对抗 benchmark｜首轮候选集

本轮先登记 **10 组场景组合**，再据此构造 **20 个题目家族、86 条主任务记录**，文学与历史各 10 个家族、43 条记录。另有 **58 条正确上游节点诊断任务**，用于后续 Oracle-CS 测量，不并入主任务数量。主任务实际覆盖 [场景目录](../../docs/benchmark-survey/07_场景总表与中文构题配方.md) 中 27 个单元。组合、题目和变体均可追溯。

这是开发与协议审查用的小规模候选集，**没有独立人工复核、没有模型实跑，也没有冻结为正式测试集**。86 条是配对及诊断变体，不能解释成 86 道独立原始问题或攻击成功案例。各家族还共享古籍来源和图模板。

版本：**pilot-v0.5**。2026-10-08起，模型题面统一采用现代文，古籍材料已忠实翻译，见 [翻译说明](现代文翻译说明.md) 和 [逐段对照](../../docs/report/2026-10-08_现代文翻译对照.md)。86条均标记为现代文，含20条无材料诊断；不能把86条当成都有题面材料。命名去重规则仍见 [保留分配](去重说明.md)。

本次已修复改名中的残留称呼和类别词误换；问法、表格评分依据及猜答案捷径先保留，见 [改名修复与后续改进](改名修复与后续改进.md)。正常古文省称按上下文理解，不额外要求别名说明。

## 组合如何选择

选这 10 组是为了用较少母题检查不同操作与扰动的相互作用：链式读取、比较、身份消解、集合算术、规则判断和时间条件各有落点，另设反向、删除、位置与改接对照。不是依据参考报告作选择，也不是给类别设最终配额。

每组先拟文学/历史各一个家族，再按 **合法关系图 → 问题 → 干扰 → 状态重算 → 标签审查** 构造。它们是本项目的候选组合，不是任何既有 benchmark 的官方分类。

| 组合 | 配方与计划单元 | 实际试题例子 | 主要比较 |
| --- | --- | --- | --- |
| C01 | 串行桥接＋共享分支＋角色假链＋同类型假桥：S01/S09/S12/S13 | 赤兔该次送礼人所引见的将领拜认谁为义父；项梁求书的信收信人任职官署在哪 | 加相关分支应保持答案，证明必须经过指定角色。 |

## 文学与历史取材

当前模型输入使用古籍片段的**忠实现代译文**，保留叙事和必要上下文，不使用提取后生成的关系句。原文、译文、片段位置及换名/反事实记录可追溯；方法见 [翻译说明](现代文翻译说明.md)、[翻译登记](modern_translations.json) 和 [原文片段登记](material_units.json)。取材如下；固定修订地址和完整摘录见 [来源登记](sources.json)。

- 文学：[《三国演义》第三回](https://zh.wikisource.org/w/index.php?title=%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9%2F%E7%AC%AC003%E5%9B%9E&oldid=2567965)、[《西游记》第一回](https://zh.wikisource.org/w/index.php?title=%E8%A5%BF%E9%81%8A%E8%A8%98%2F%E7%AC%AC001%E5%9B%9E&oldid=2562136)。
- 历史：[《史记》卷七·项羽本纪](https://zh.wikisource.org/w/index.php?title=%E5%8F%B2%E8%A8%98%2F%E5%8D%B7007&oldid=5978360)、[《史记》卷四十八·陈涉世家](https://zh.wikisource.org/w/index.php?title=%E5%8F%B2%E8%A8%98%2F%E5%8D%B7048&oldid=2531218)。

8 个家族以古籍片段现代译文构题（C04另有白话文纸色干扰），C08 的 2 个家族同时使用古籍现代译文与现代合成比较分支，另外 10 个家族为原创白话文文学目录/历史档案风格的规则世界。合成作品、人物、馆年和页数不是史实主张。小说事实按作品世界处理，史书事实按所给记载处理，原文并不能自动等同已核实的历史真相。

`quote_ids` 标识原文事实标注依据；模型读到的是忠实译文，古籍原文保留在溯源文件中，译文没有被事实句替换。跨片段关联可引用多个锚点，完整支持材料记录在 `fact_to_evidence_all`，例如陈涉/陈胜、吴叔/吴广的别称识别也需要引文材料。C08 修改来源关系时，新的事实标为 `counterfactual_editor_override`，原锚点移入 `parent_quote_ids`，不能拿它证明改写后关系是原书内容。换名直接作用于原文中的实体和明确别称，需结合 `entity_mapping` 及 `material_annotations` 回溯替换位置；变换后的文本不称“未经改写原文”。

采集日期为 2026-10-07，核验状态是本轮助手阅读网页，尚无独立人工审稿。页面显示 [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)，底本、编校贡献及网站条款在来源登记分别说明。摘录与改写保留署名和固定页面链接。当前不附加覆盖来源条款的新数据总许可证，发布前须明确材料与原创增补的许可边界。

## 处理模型背景知识干扰

从用户指定的 [多跳A组 AI构造分析](thread://01a113c1-16a5-77e0-b5dc-75136a5a14ff?hostId=local) 恢复的问题是：熟悉人名、称号、剧情关系甚至匿名后的叙事结构，都可能让模型绕过上游证据。相关设计恢复与多步骤判分见 [报告09](../../docs/benchmark-survey/09_多步骤评判与核心创新点回收.md)。历史讨论中的实验数字未当作本轮结果。

每个家族保留原始基础题、三类挑战中的一种，以及必要的实质对照。三类挑战指命名挑战、匿名挑战、陌生名挑战；保留分配与具体限制见 [去重说明](去重说明.md)。本版为pilot-v0.4，总计86条，移除42条表面命名重复，不再提供每个家族的三命名完整交叉。无材料诊断使用所保留挑战的同一问句，不能据跨家族命名差异直接估计知识干扰的因果效应。

C08 的两个主要反事实图通过**相同关系的两条边交换终点**构造，保留所有实体以及逐关系入出度；旧答案仍在材料中，但原起点的完整路径已改变。另有两种协议检查：

- 同一改接材料换问题起点，正确终点应改变，排查不读问题只扫端点。
- 专门建立两条同长度链汇到同一终点的材料，再以两个不同起点各问一次，答案相同而所需前驱证据不同。两题材料完全一致；该附加图不宣称保度数。

C04 无缺失占位符；删除的是实际材料，其他句继续保留。删一处重复支持仍有替代证明。删除必要/无关内容尚未做等 token、等文风匹配，不能将其裸分数差解释为纯逻辑效应。

C07 背景恢复为已登记古籍片段的重复与裁切，支持按实际摘录分布；重排对照严格反转相同材料。文学题的国界与部洲来自同一段真实原文，不能人为拆成两份独立材料，因此该家族不再标记三处远隔支持S16；历史题仍分布在三份摘录中。报告单位为字符，尚未针对任何模型 tokenizer 计数，也没有真实检索工具或百万 token 长窗实验。

## 样本、证明与追溯

主任务每行一个 JSON 对象。关键字段：

| 字段 | 含义 |
| --- | --- |
| `id / family_id / combination_id / variant` | 不透明题目 ID、题目家族、先行组合及变体。 |
| `scenario_ids / scenario_annotations` | 实际场景单元及机制解释，可链接场景目录。 |
| `input` | 与模型输入导出一致的清洁题面。材料只带不透明 ID 和文字。 |
| `facts / query` | 关系化事实和类型化查询；用于程序重算，不能替代人工检验自然语言是否等价。 |
| `gold` | 状态、答案、合法证明列表、歧义解释及规则真值/假设。 |
| `fact_to_evidence / fact_to_evidence_all` | 主要材料及完整支持材料列表；同一段可支撑多跳，别称和授名背景也计入实际支持。 |
| `material_style / material_registers / material_annotations` | 古文、白话文或混合分组；逐份材料的字形、引文片段、精确替换与背景裁切记录。均留在标注侧，不送入模型。 |
| `material_label_scope` | 当前输入类别，或无材料诊断所继承的母题类别。 |
| `gold.proofs[].dependencies` | 证明节点之间的有向依赖；不是模型隐藏思维链。 |
| `source_cluster_id / quote_ids / source_links` | 来源聚类与引文溯源；混合世界另有原始锚点记录。 |
| `control_id / challenge_id / paired_changes` | 家族配对与比较对象；新增、删除、改写的事实 ID、问题/答案/状态变化。 |
| `entity_mapping / construction` | 可逆实体映射、随机种子、噪声字符数、顺序与改接参数。 |
| `attack_design / expected_wrong_answers` | 目标失误、预想错误路径及验收条件；是待验证假设。 |
| `review / split` | 候选状态、人工与模型复核情况；所有题均为开发划分。 |

参考证明记录节点 ID、操作、预期结果、支持事实/材料、上游值及依赖。C04 两条重复支持是**两个有效证明**，没有伪装成独立来源。C03 的歧义证明包括“别名 → 指定身份”节点，然后连接馆、馆长、书房。C06 表格与完整文本名录做实体连接，包含范围枚举、逐行过滤和求和；实际最长依赖深度为 5，操作总数另算。

主任务有 60 条可作答、4 条歧义、22 条材料不足。C09 中“不确定”是逻辑判断题的合法答案，`status=answerable` 且 `logical_truth=unknown`；它不同于没有材料或删掉桥的 `status=insufficient`。本轮没有显式事实冲突题。参考证明深度为 2–5；材料不足记 0，此值不能解释成单跳题。

没有隐藏测试集。后续划分须将全部家族变体放在同组，并进一步检查来源、实体、关系图、组合模板的连通共享。已有 `source_cluster_id` 是辅助标签，**并未计算全局连通分组**；不能仅凭该字段随机拆分而声称防泄漏。当前 4 个真实来源和高度复用图，只适合流程试跑和审题。

## 预备评测方案

按 [多步骤协议](../../docs/benchmark-survey/09_多步骤评判与核心创新点回收.md) 进行后续试跑。本轮提供标注和诊断输入，尚未实现/冻结正式评分器，更没有填写模型得分。

- **答案与状态**：答案集合规范化后精确匹配；歧义题须匹配解释—答案，材料不足须拒绝补事实。不把任意猜对的文学答案当成功。全体主任务为状态分母，可答/歧义/不足另报分组。
- **Strict SR**：可答主任务中答案正确且完整合法证明通过的题数 / 可答主任务数。多证明时必须有**一条完整一致的合法证明**；不能从不同参考路径各挑有利节点拼接。歧义和不足的行为合规率分别统计。
- **Path-CFS**：按提交的简短证明逐节点判断局部合法性与上游依赖，再以节点权重相等汇总，并同时报告端到端结果。必须要求起点与题面一致，缺节点不得靠只提交末端来缩小分母；按一个匹配的完整参考操作图确定分母。它评价可观察提交物，不等于 DAComp 原始执行流水线分数，也不等于内部推理正确率。
- **Oracle-CS**：独立运行 58 条节点题，正确节点数 / 58；它们仅覆盖基础对照的关系查找节点，未覆盖比较、求和、溯因等全部部件。不能把普通输出中“步骤答案与 gold 相同”冒称 Oracle-CS。扩充全部部件后再报告总体组件能力。
- **配对鲁棒性**：保持型扰动报“两题 Strict SR 都通过的配对数 / 有效配对数”，另报条件失效率“基础题通过而扰动题失败 / 基础题通过的有效配对数”。改变型扰动报按各自 gold 更新成功率；匿名化须反向映射后比较。分母为零时记不可计算。
- **协议有效性**：分开统计无材料证据约束、重复支持/全删桥、同材料换起点、同答案换证明和保度数更新的通过率。C03 澄清与 C10 时间条件各有独立配对，不能混入答案保持型扰动。

先逐家族展示全部条件，后宏平均家族/组合；区分有效配对数、题目记录数和原始家族数。正式置信区间与显著性设计需按共享来源/图聚类处理；本批不能支持稳健的总体能力推断。

## 重建与验收

从项目根目录，用现有 Python 环境运行：

