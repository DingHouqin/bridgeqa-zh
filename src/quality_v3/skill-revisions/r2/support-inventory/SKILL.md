# 按边登记来源支持：R2候选

对requested_edges逐条核查，不能只输出最显眼的一条边。先确认每边的child、parent、角色、scope和在当前材料中有依据的别名；逐次查找这些称谓的全部实际出现，阅读各出现位置的上下文。focus_windows只是检索线索，不保证包含所有支持，也不证明窗口中的句子就是证据。

每个独立支持组须同时完成两件事：确定这条关系连接的具体两人，且实际表达所要求的父／母关系。关系句中的代词、称号、“长子”等承接词需要身份先行词时，把先行词和关系句共同列入该组。允许非连续引文合取，但不能把合取组拆成多个各自不完整的“替代支持”。

出生日期、排行、改名、在场或身份证明句，若没有亲属关系谓词，只能辅助消歧，不能单独登记为父母边。反过来，一句只说“他的父亲”但没有可确定的先行词，也不是完整独立支持。登记前逐组自问：只保留这一组和其明确列出的身份依据，是否仍能确定请求边？否就补入当前材料中的必要依据，或记为尚未支持；不得凭常识补足。

多组各自完整支持同一边，才是重复表达。独立证明须比较整条查询路径：替换的关系边不同，且其余必要边仍受到材料支持；换同一边的引文不算另一完整路径。保留角色、方向、时间／事件和现实／梦境范围，不从配偶生子推出丈夫亲生父边。

对每条请求边报告支持组或明确未解决原因，再讨论删一组／删一条链后还保留什么。没有登记完是not_constructed；完成给定范围检查仍无适用结构才not_applicable并说明依据；解释冲突是unresolved。程序负责定位与精确删除，技能不能以一次搜索未发现证明穷尽，也不自行放行。此为待继续修订的R2候选。
