# 执行与质量规范

版本：v0.4开发验证；旧机制纳入日期：2026-10-21。当前机制入口见[总览](../README.md)，结构见[详细架构](../architecture.md)。FamilyV2约束以[删证与审查首批验证规范](deletion-review-v0.2.md)为准；质量修订见[技能试验规范](quality-skills-v0.3.md)和[多轮迭代协议](skills-iteration-v0.4.md)。旧版冻结数据及日期化记录保留当时状态。尚待实现的总体需求保留于[设计记录](../design/2026-10-20_多智能体构题系统方案.md)。

## 1. 目标与当前能力

生成单位为基础任务及其条件家族。题目必须确实依赖至少两步信息操作，不能用跨文档数量、文本长度或预设图边数代替文本中的多跳性。允许同段证据，同段／跨段／跨篇另行标注。

当前来源家族实现支持直接父母事实与连续两次父母查找，主要干扰选用已取得的来源材料，是否构成实体混淆或假桥接须另行核验。本轮新增明确标记的合成审查挑战，不等于已实现通用合成／反事实构题。时间、比较、集合及阶段性关系求解仍待开发和验收。

## 2. 角色与信息合同

| 角色 | 输入与输出 | 边界 |
| --- | --- | --- |
| Origin | 冻结现代文 → 实体、父母事实、父／母角色、陈述范围及支持证据组 | 不补百科事实；关系方向为 parent→child；不同 scope 不无条件合并。 |
| Composer | 已审事实及程序枚举的查询 → 基础问题、查询、答案、证明与材料选择 | 查询方向为 child→parent，连续两次；检查直接答案与单跳捷径。 |
| Difficult | 已审基础题、材料与配方许可 → 困难方案、干扰来源及预期错误路径 | 不自行扩大困难机制范围，不编事实补救来源不足。 |
| Supervisor | 对应阶段版本及检查结果 → 裁定、证据位置、缺陷与修订范围 | 独立上下文检查，不将生成者自评视为放行依据，不静默修改被审对象。 |
| Blind Solver | 题号、问题、给定材料、回答政策及输出结构 → 可答状态、答案、逐字引文和简短操作步骤 | 不见答案、事实图、证明、配方、条件标签或其他变体；每变体独立无工具会话。 |

五个角色是同一 Flash 服务上的职责分工，名称不同不保证错误独立。项目角色预设不等于 Harness 内置子智能体预设。旧版字段见[合同 Schema](../../src/multi_agent_v0/schemas.json)和[角色预设](../../src/multi_agent_v0/role-presets.json)，FamilyV2见[版本化合同](../../src/deletion_review_v2/contracts.py)。本轮来源与蓝图由程序／根GPT代理约束并显式修订，Flash角色建议不能表述为自主完成全部构题；加载入口见[实现说明](../implementation/README.md)。

事实的每个 evidence_set 内为共同支持，不同 set 之间为替代支持。引用必须定位于实际材料；图求解不能证明自然文本中不存在未抽取的答案路径。直接表达／指代消解与目标结论的直接读取／多步组合分别标注。

## 3. 执行与家族规则

前置材料按[现代化规范](2026-10-21_红楼梦选段现代化规范.md)冻结后进入 Origin。随后依次执行事实检查与审查、基础题求解与审查、家族变换与审查、独立盲解、最终核对及程序打包。各检查绑定对应输入版本。

| FamilyV2共同成员 | 相对基础题的操作 | 验收目标 |
| --- | --- | --- |
| 基础题 | 提供完整必要材料 | 答案及合法两步证明明确。 |
| 主要干扰 | 加入适用的来源型干扰材料 | 正确答案与基础证明保持，错误连接及预期错误路径明确。 |
| 无关添加 | 加入语义无关材料 | 答案与基础证明保持。 |
| 保留起点名称的必要支持删除 | 删除必要支持，起点名称须在原材料其他位置真实保留 | 登记图及自然文本完整支持均消失，预期证据不足。 |
| 无关删除 | 删除不影响答案的内容 | 答案与基础证明保持。 |

适用时增加名称同时消失的必要删证、重复支持删除、替代证明保留；后两者分别登记重复表达与独立完整证明，不适用须写原因，不能强凑。无材料诊断单列，不计入主成员。旧版四成员数据及读取能力保留。若材料不够构成可靠家族，拒收或报告失败，不伪造缺证条件。引文不再匹配仅能触发文本复核，不能证明事实消失；成员只使用实际交付材料判可答性。模型答对不构成淘汰理由，模型答错也不自动证明题目有效。

## 4. 修订与争议处理

- 来源缺必要事实直接拒收。问法、标注、格式或干扰实现错误可限次修订；当前默认格式重试与内容修订各最多两轮，初稿另计，不无限循环。
- 保守格式适配只补缺失闭括号、将已知说明字段保留至 warnings，并记录插入或迁移；不能更改事实、身份、scope 或引文以强行通过。
- 重要分歧交 GPT 显式裁定，保存争议、来源、父版本、裁定与定点修改；再由程序及独立 Flash 会话复查。当前入口不是无人值守的自动 GPT 服务。
- 本轮机器交付后由不参与Flash构题及三条件实验的GPT子智能体进行实验前参考审核、实验后运行与统计审核；仍不能裁定的来源解释、标签或修订争议交人工。取消本轮固定随机抽审，不改写旧记录人工状态。条件间判断差异本身是实验结果，不自动转人工。争议未处理不阻塞机器交付，但对应案例不得正式放行，并从确定标签主分析排除。
- 来源、材料、问题、证明、答案或协议变化，应使受影响的下游检查失效并重做。不得按模型成败挑选重跑结果或覆盖冻结响应。

## 5. 隔离、记录与放行

Blind Solver 使用独立运行数据目录；图工具、文件、Shell 及工作目录工具关闭。程序对实际请求执行输入隔离核对。凭证只由运行环境传递，不进入文档、题库、模型上下文或日志。

固定并记录来源、材料哈希、配置、模型返回标识、Skill、合同、协议及评分版本；未固定的 temperature／seed 如实记为未固定，不将模型别名写成不可变权重版本。缓存仅复用输入、提示、合同及配置一致的记录。

程序将被测输入与内部gold、证明、标签分开导出。开发交付、机器检查、GPT独立审核、人工裁定及正式发布分别记录；GPT审核不得统称人工真值。本轮A/B/C仅比较生成说明和实际批准库提示，隐藏参考、先前结论及程序通过／失败结果，详情见[实验规范](deletion-review-v0.2.md)。当前评分不等于完整分层评分器，也不代表观察到了内部思维过程。

完整家族与变体不得跨开发／保留测试划分。正式批量构建需额外完成去重、共享来源／实体／模板分组、覆盖与失败统计；现有一次开发家族验收不能替代这些程序。

验证依据与尚未满足的验收条件见[验证索引](../validation/README.md)。

## 5.1 质量修订与技能迭代

新增[质量模块](../../src/quality_v3/README.md)采用单成员审查输入：Supervisor不同时收到其他成员、删除前文本或删除引文。家族变换之间的不变量由程序另外比较；局部可答性只能用该成员实际交付的contexts判断。提交证明的有序事实、角色、方向和顶层答案由程序检查，不能靠审查员心中重排后放行。

评分分别记录状态、最终答案、证明支持和引用定位。别名须唯一指向同一已绑定实体；引用与旧标准区间不相交只触发语义复核，不单独判错。语义评分不得替候选补写或更换空／无效引用。正确的缺证声明可以使用空答案与空证明；模型无法解释的情况与确定错误分开记录。旧分、原始裁定与程序门禁结果分别保存。

四项项目技能用于两步必要性、成员证据、语义评分和支持登记，随对应角色显式加载。技能正文是待验证的能力干预，不代替合同、隔离、精确删除或独立GPT审核。至少先进行三轮：每轮冻结候选技能、回归前轮案例、加入独立新例，分析收益、误拦、误放和未决代价，再决定下一轮修订。前轮新例一旦被用于修订，即改称回归，不能继续称未见测试。达到三轮也不自动表示定型或允许扩大自动放行。

相同回合generic／skills使用相同材料、Schema和程序门禁；共享检索窗口和查询卡不能算成技能收益。窗口仅标出待核字面位置，不裁定事实或证明独立性。运行、参考、提示和技能版本不原地覆盖；协议失败不当拒收，未决不当错误，不按结果挑选重跑。实际进度以[验证索引](../validation/README.md)为准。

## 5.2 确定结论与人工／强智能体复核

2026-10-23起，本轮评分及支持登记按用户最新要求采用[零错误优先分流规范](review-routing-v0.11.md)：确定输出至少不能有已知错误，允许明确交付“需【人工/强智能体复核】”。非空自然语言来源默认独立复核；原始失败、模型未决、模型组审通过均不能自动变成确定评分或合格支持。

原交付状态、复核状态与可用的确定结论分别保存。没有与同原输入／原字节及明确范围绑定的实际可信审核时，确定conclusion为空；原raw辅助判断和自由理由不随核心收据扩签。强智能体独立审核后仍有争议的继续待办，不能靠同模型新session自签。实现和开发回放的证据见[本轮报告](../validation/2026-10-23_零错误优先与复核分流.md)。

全任务分流分母保留失败及待复核，同时报告自动确定覆盖、审核后覆盖与待办比例。转复核是合法路由交付，不计语义正确或模型已修复；全转复核不证明自动化有效。此前冻结批次的实验分母、原始评分及争议处理状态保留原口径，不回写历史。当前新增的是可调用门禁及已有数据回放，旧冻结运行器未被静默替换，正式发布仍关闭。

## 6. 外部关系库与阶段性关系

用户已要求先核验、整理外部关系库优缺点，再经确认使用。候选下载、试查与审查不构成接入批准；状态见[候选入口](../resources/relationship-libraries/README.md)。外部比对只提供交叉检查线索，不能覆盖来源scope、补gold或补回删证支持，不能进入Blind Solver。

用户已批准C01候选比对与C02冲突提示；[静态比对器](../../src/multi_agent_v0/external_relations.py)及Supervisor调用位置已完成程序验证，详情见[接入记录](../validation/2026-10-21_关系库辅助核验接入.md)。本批三条件实跑已完成，见[实际报告](../validation/2026-10-22_删证与审查首批验证.md)；非空提示不代表关系已核验或审查可靠性改善。未批准候选、用途越界、提交或文件哈希不符时停止，而不是静默回退或扩大权限。

朋友、敌意、雇佣等关系须保留时间、事件、条件与视角，不默认永久有效。扩展合同、题型及验收要求见[外部核验与阶段性关系规范](relationship-validation.md)。阶段性关系仍属待实现能力，静态表遇到时间限定时不强行匹配。
