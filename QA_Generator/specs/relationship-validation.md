# 外部关系核验与阶段性关系

日期：2026-10-21。用户新增要求：可使用现有人物关系库辅助核验，但须先核验、整理优缺点并经用户确认；朋友、仇人等关系可能具有阶段性，并可用于多跳任务。

本页是机制约束与扩展设计。当前父母关系原型保持原合同；C01/C02外部比对器已按用户批准范围实现并完成离线验收，动态关系合同与时间求解器**尚未实现或验收**。资料见[关系库入口](../resources/relationship-libraries/README.md)，已完成内容见[接入验证](../validation/2026-10-21_关系库辅助核验接入.md)，主流程见[执行规范](workflow.md)。

## 1. 外部关系库怎样进入核验

确认前只允许获取、解析、审查与比对试查，不能接入生成、审查放行或标准答案计算。逐库记录固定版本、来源、字段、许可情况、错误、适用范围与用户决定。下载成功、AI建议及文件状态都不能替代用户批准。

用户已批准的数据流为：Origin先基于冻结文本独立抽取 → 程序完成基础检查 → 独立外部比对器对已抽取关系检索候选 → Supervisor对照实际来源处理一致、冲突及遗漏提示。程序调用位置已接入并用无模型桩验证，尚未使用新提示进行Flash实跑；没有新增第六个AI角色或部署服务。C01允许静态相容、遗漏及冲突提示，C02仅冲突提示，不输出正向佐证或遗漏建议。

外部库只作交叉检查：

- **吻合**：名字、方向、关系、版本与限定可比，存在相容记录；不能因此自动通过。
- **冲突线索**：发现可能相反的关系，先排查方向、别名、同名、版本、亲生／收养、说话者及时间，不能直接认定Origin错误。
- **未覆盖**：未找到记录，不等于关系不存在或题目应淘汰。
- **不可比**：名称不能可靠消歧、无阶段信息、对象是机构或复合字符串、只有共现边等，不强行归类为冲突。

同源或内容重复的库归为同一来源家族，不按仓库数量投票。关系方向转换必须保存原记录与规则；“子”只能支持泛父母连接，不凭端点名字推断父／母或亲生身份。“朋友的朋友”不能自动推导朋友，“敌人的朋友”不能自动推导敌人。

**任务的最终依据仍是选定版本与实际给定材料。** 人物发言、传闻及假设的内容不能被外部全书人物图覆盖。库中有关系但删证后的材料没有支持时，题目仍是证据不足；不能把外部库的正确关系喂给盲解、补回材料或判其应可答。反事实／合成轨与来源轨分开，预定改接不是对原著抽取的错误，不能被外部图“纠正”。

## 2. 关系不是只有一条无时间的边

至少区分三类：血缘等通常稳定的身份关系；婚姻、雇佣、主仆、任职、居住等可能变化的社会状态；友好、敌对、信任、结盟等带方向、程度或视角的互动状态。稳定性由谓词合同决定，不能默认所有亲属标签都永久成立，尤其不能混淆生母、继母、养母与称谓。

朋友、仇人等关系应记录**谁对谁、何时、在什么事件／条件下、是谁的陈述，以及什么证据支持**。一次争执不自动等于“从此成为仇人”，曾是朋友不保证后来仍是朋友；没有后续材料时记未知，不自动延续或取反。友谊、竞争与冲突也未必互斥，只有合同明确声明的状态才作互斥处理。

不要把主观情绪、单次行为、人物评价与持续关系当同一种事实。关系是否对称、是否允许继承到后续事件、有哪些逆关系和推导规则，都须在谓词定义中明确；没有规则就不补边。

## 3. 拟扩展字段

以下为待实现的语义合同，不是当前可执行Schema的新字段；正式接入前需生成版本化Schema并补校验与求解。

| 字段组 | 要记录的内容 |
| --- | --- |
| 身份与关系 | 稳定人物ID、主客体、谓词、方向；别名及消歧依据。 |
| 有效范围 | 故事事件ID、阶段或有效区间、成立条件、起止是否明确、边界不确定性。 |
| 叙事定位 | 版本、章段与引文位置、叙述顺序；与故事实际时间分开。 |
| 陈述地位 | 叙述者／人物发言／传闻／猜测／梦境等scope、陈述者及肯定／否定状态。 |
| 状态变化 | 新建、延续有据、结束、改变、存在冲突或未知；关联前一断言及变化证据。 |
| 支持 | 正反证据、共同及替代支持组、原文与现代文映射、来源及文本版本哈希。 |
| 外部比对 | 经批准的库版本、原始匹配记录、名字与方向映射、相容／冲突／未覆盖／不可比、处置原因。 |

不能用“第三十回”直接代替关系从第三十回开始；叙述可能回忆往事，同一章也可能有关系变化。发生时间、被叙述时间与人物得知时间分别记录；无法确定时保留部分顺序或未知，不虚构日期和持续区间。时间未知不等于“永久有效”。

## 4. 怎样构造多跳题

先冻结问题的目标事件／阶段，再设计必要依赖与干扰。每条边是否适用由查询计划决定：同一阶段的组合要有相容的时间与条件；跨阶段任务则显式说明各步的阶段和先后约束，不能把所有边机械要求落在同一时间点，也不能任意跨阶段拼接。

| 题型候选 | 必要多步操作 | 可研究的困难与对照 |
| --- | --- | --- |
| 阶段内关系链 | 筛选指定阶段成立的关系，再沿其找到另一人物或属性 | 旧朋友／旧任职与当前关系混淆；保留同量无关旧信息对照。 |
| 变化前后定位 | 定位事件及前后阶段，再追踪指定关系的对象与其后续连接 | 用后来的关系代替问题指定时刻；独立核验每个阶段的答案。 |
| 视角限定的阶段关系 | 先找指定人物在事件中的陈述，再组合该范围内的关系 | 把别人的猜测或敌意投射为客观双方关系；加入不同视角但可消歧的材料。 |
| 变化证据删除 | 去掉改变关系的必要证据，再检查问题能否回答 | 不凭常识延续旧状态；既无持续规则又缺新状态证据时应保留未知。 |

例如仅用于说明的**合成例子**：阶段甲明确记载甲与乙为朋友，乙在东社任职；阶段乙明确记载甲与丙为朋友，并说明前段友谊已结束，丙在西社任职。问“阶段乙，甲的朋友任职于哪家机构？”需先按阶段选朋友，再查其任职关系；阶段甲的乙—东社链可作时间错配干扰。这里的字母人物和机构不是《红楼梦》事实，不作为本轮已生成题目。

实际文学题必须有冻结文本支持这些状态和限定；若只有“甲与乙吵了一次”，不能擅自把后续阶段标作仇人。若“朋友”不唯一，必须限定对象或允许集合答案，不能靠预选链隐藏其他合法答案。

## 5. 接入前的最低验收

1. 用户批准指定关系库及用途，身份、方向与来源家族映射可审计；批准不扩展为执行上游程序或调用外部付费服务。
2. 程序能处理同一人物在不同时段与不同scope的断言，检查时间及条件相容性；覆盖已知开始、已知结束、边界未知、回忆叙事与阶段内变化等反例。
3. 比较外部库时没有时间字段必须返回不可比或仅静态提示，不能据此裁定阶段关系真假。
4. 逐个变体重算全部许可证明及答案状态，检查删证、替代支持、多对象、跨阶段错接与原文直答捷径。
5. 盲解输入不含外部关系库、内部时间图、标签或其他条件答案；完成独立盲解、Supervisor文本核查及人工争议处置。

当前已完成候选下载审查、用户审批、静态比对适配与事实审查调用位置的程序验收；动态求解和新提示下的新题实跑仍待后续验证，不改写已有冻结家族的验收范围。
