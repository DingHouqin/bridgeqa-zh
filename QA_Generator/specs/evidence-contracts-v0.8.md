# 支持出现位置与评分合同 v0.8（开发试验）

本版继续修复[v0.7 实跑暴露的失败](../validation/2026-10-22_支持覆盖与旧评分继续修复.md)。协议通过、引文定位正确和模型自评通过均不等于语义修复成功；未知、协议失败和未运行分别统计。本版仍是开发回归，不发布正式题集。

## 登记：每个位置都作答，每个正支持都复核

[登记组件](../../src/quality_v3/inventory_occurrences_v8.py)沿用[v0.7 非重叠原文分区](../../src/quality_v3/inventory_coverage.py)，每次仅要求一个目标事实、最多八个待判断单元。完整原文单元表供模型选取必要前件，但每个事实与每个单元的组合恰出现一次，不能用一个长组覆盖多个未登记位置。冻结 16 个来源共 612 格、96 个窗口；这是任务覆盖量，不是正确支持数。

每格保留 supported / unsupported / unknown 原始判断。正格必须指向在当前单元完成的独立关系断言，并登记所需前件、child 与 parent 的原文定位，以及谓词、父母角色和语境锚点。“生二子”与随后“长子乙”可以共同构成一次断言；不能因为组内某句出现了关系词，就把该组每一句都算成一次重复支持。问答可用问题、发言者和回答共同完成关系，但不能省略实际主体前件。

相同引文范围只生成一份规范支持组；每个原始正格及其断言位置仍保留，并逐个复核。共享前件或包含较短组的较长组不自动重复，也不自动成立。独立验收须辨认是否确有另一次断言，不能以引用长度、嵌套关系或模型的组数代替语义判断。

每个正格的第二次模型审查仅看到该组的原文、精确主体定位、锚点、目标边和组内纯身份别称。自由理由、其他组和未选取原文不作为其证据。父亲、母亲与通用家长分别核验，子辈“儿子/女儿”不证明 parent 的性别；假设、转述、否定和现实陈述不能混用。

组内 child / parent 的原文表面必须是唯一的纯身份名或别称。带“乙之父”等关系描述的登记名不能补足缺失的角色依据；展示名也走相同过滤，没有安全且实际可见的身份表面则明确标记未解决。此过滤是防止元数据补边的负面限制，不是完整的人名语义解析器。

规范路径明确由程序根据正支持提案构造，不声称模型原本正确提交了路径。全负来源单列 no_positive_occurrences_requires_source_review；含 unknown 则单列待裁定。零正既不自动证明无支持，也不混入真正未知的分母。

单窗口验证只验证该请求内部的绑定和结构。最终组装必须接收可信、冻结的原始登记请求，重新生成全部窗口并验证摘要；不能把可重算的自声明摘要当作原文认证。

## 评分：约束交付格式，保留原始语义判定

[评分包装器](../../src/quality_v3/scoring_review_v8.py)继续调用[v0.7 逐步证据与全文逐跳核心](../../src/quality_v3/scoring_review_v7.py)。阶段 A 只看当前候选步骤提交的引文；阶段 B 核全文的每跳、每个当前主体及全部 context，并逐一复核原引文语境。阶段 B 的好路径不能补救原提交步骤的坏引文或未知状态。

本版允许并保留 hop 层可选的审计 reason；适配器仅移除此已声明的自由文字后调用旧核心，不补边、不改 verdict、不删错误字段。按当前请求动态约束 step、hop、context ID 与列表长度，空证明的 context_checks 必须为空，但仍需从 query.start 遍历全文。每条边与每个支持组仍需各自理由和可核原文。

实体 ID 解析后的 query.start 展示名也经过纯身份过滤。所有唯一、纯净的登记名和别称继续保留为身份索引，避免误删只出现在候选步骤或 query.start 的合法别称。具体模型请求仍仅投影该阶段局部可见的别称映射；不得用未提交全文选择阶段 A 的身份名。没有纯身份表面时使用不含关系的占位符并保持 unresolved，不能计作确定缺边的正确拒答。

## 冻结与验收

[运行器](../../src/quality_v3/contracts_v8_experiment.py)与[分析器](../../src/quality_v3/contracts_v8_analysis.py)冻结案例、参考、任务顺序、协议、初始请求和依赖代码摘要。54 个任务包括全部 v0.7 案例及独立编写的 2 个评分、2 个登记开发挑战；案例作者接触过先前方案与失败，这些新增案例不构成正式保留测试。参考另由非作者盲审，组件和运行器也交叉验收；不通过的版本保留退回记录。

模型仍为用户指定的 deepseek-flash，四个 worker，单次输出上限 12000 tokens，工具关闭、每阶段独立 session，最多三次格式尝试，所有尝试留痕。54 个任务计划 188 个基础阶段，正组复核次数取决于原始输出；应用格式重试、SDK 内部重试、返回的独立 session 分开计数。任一登记窗口失败仍执行后续窗口并保留各窗口结果；有失败时不拼装为成功交付。不对终态失败选择性重跑。

本版未同期重跑基线，因此与保留的旧结果仅作开发诊断，不能声称单因素因果增益。实跑后必须由非组件作者核原文、每格标签、各独立支持、主体完整性、方向、角色、语境和路径，再核评分中正确拒答与独立正确下游步骤。结构完成、模型复核通过或待裁定均不得算修复成功。结果写入[本轮验证报告](../validation/2026-10-22_支持覆盖与旧评分继续修复.md)。
