## 先做什么

从 [当前86题](../data/pilot_literature_history_v0/README.md) 中选10–15题，尽量包含文学与历史、普通串联、多分支、表格、规则、多解和材料不足。先用几家厂商中能力较弱的可用模型试跑，确认输入、回答保存和评分能走通，再扩展到全部86题。模型和费用按小组可用条件确定。

正常作答使用 [模型输入](../data/pilot_literature_history_v0/inputs.jsonl)，不要把参考答案或正确证明放进提示词。记录实际使用的模型名称和版本、运行日期、提示词及主要生成参数；保留原始回答，调用失败也要留下记录，不能把未作答当作答错。

## 必须做出的东西

- **真实运行记录。** 每条能对应到题号、模型和原始回答。先交一批试跑结果，随后覆盖全部86题；若有调用失败，标明原因并补跑。
- **错误整理。** 用 [评分器](../evaluation/README.md)或尚在讨论的人工规则逐题判断，记录答案是否正确、首个出错步骤和主要错误类型，例如找错对象、关系方向错、漏条件、时间混淆、错误拒答或忽略材料。
- **难度表。** 为每题给出“易 / 中 / 难 / 待定”及简短依据，并列出支持判断的实际回答。多数试测模型能顺利完成可暂列“易”；表现不一或局部步骤容易错可列“中”；多个模型在同一必要步骤反复失败可列“难”；样本不足、题目有问题或结果不一致则列“待定”。这些是试测参考，不能只凭跳数或阅读感觉定难度。
- **需要修改的题目清单。** 把疑似题面不清、标注错误、缺证或存在捷径的题号与具体原因交给两位核查人讨论，避免把题目问题当作模型能力不足。

对于“后面的步骤为什么错”，可另用 [正确上游输入的小题](../data/pilot_literature_history_v0/oracle_inputs.jsonl)检查：给对前一步后能做对，说明可能是上游错误传下来；仍做不对，才有依据认为这一步本身较难。这类诊断与整题正常作答分别记录。

## 怎样算完成

86题均有真实作答记录或明确的未完成原因；每题都有判分、主要错误分析和有实测依据的难度结论；别人能从难度表找到对应的原始回答。之后拿到正式模型测试组的结果，还要据此修订难度，而不是把首轮弱模型的表现当作最终结论。
