# 03｜长上下文与大规模干扰：增加什么，才能测出什么

[返回入口](README.md) · [资料目录](00_范围与资料目录.md)。

## 1. BABILong：模拟事实嵌入真实长背景

[BABILong 论文](https://proceedings.neurips.cc/paper_files/paper/2024/file/c0d62e70dbc659cc9bd44cbcf1cb652f-Paper-Datasets_and_Benchmarks_Track.pdf) 与 [作者说明](https://github.com/booydar/babilong) 将 bAbI 模拟世界的事实句分散到 PG19 书籍背景文本中，保持模拟任务的答案。任务套件来自 20 类 bAbI 能力，论文核心长上下文实验重点覆盖前五类；不能把所有长长度实验都说成对 20 类等量覆盖。仓库提供不同长度、任务和规模版本，最长设置可达千万 token。

**中文迁移示意。** 事实“林澄把钥匙交给方宁”；后面隔大量背景出现“方宁走到望湖馆”；问“钥匙现在在哪里？”答案取决于物品持有与位置状态组合，背景可以插在事实之间。若后来出现“方宁放下钥匙”，则答案不能再跟随方宁移动；因此插入材料要避免改变同一模拟世界的状态。

**本调研分析。** 长背景主要检验找到并连接分散证据，未必制造语义上有诱惑力的假链。可以再叠加共享角色的事件干扰，但需分别记录背景长度和任务事件数。基准长度标签也不代表每个模型 tokenizer 下恰好同长。

## 2. RULER：四大类别与 13 个配置

[RULER 论文](https://arxiv.org/abs/2404.06654) 旨在区分声明的上下文容量与实际使用能力；[官方说明](https://github.com/NVIDIA/RULER) 支持检索、变量追踪、聚合和 QA。下表根据本轮读到的 [官方配置源文件](https://raw.githubusercontent.com/NVIDIA/RULER/main/scripts/synthetic.yaml) 整理，配置可随仓库更新，复刻时需固定版本。

| 官方配置名 | 构题方式与干扰因素 |
|---|---|
| niah_single_1 | 噪声背景中放一个文字键—数字值。 |
| niah_single_2 | 文章背景中放一个文字键—数字值。 |
| niah_single_3 | 文章背景中改用 UUID 值，减少熟悉答案的帮助。 |
| niah_multikey_1 | 在文章背景中放多个键，只问目标键。 |
| niah_multikey_2 | 背景含其他 needle，目标仍为文字键—数字值。 |
| niah_multikey_3 | 键和值都用 UUID，背景含其他 needle。 |
| niah_multivalue | 同一目标键有多个值，需要全部返回。 |
| niah_multiquery | 同时查询多个键，需要完整作答。 |
| vt | 变量别名链；当前默认配置一条链、四次绑定。 |
| cwe | 混入不同出现频率的词，提取共同高频词。 |
| fwe | 从频率分布识别高频词。 |
| qa_1 | 基于 SQuAD 的 QA 长上下文构造。 |
| qa_2 | 基于 HotpotQA 的 QA 长上下文构造。 |

**变量追踪示意。** “对象 A 记作 B，B 记作 C，C 记作 D；另一条链 X→Y→Z”；问 A 的最终别名，答案 D。多条外形相似的链会诱导模型把 B 接到另一条链。它可用来隔离组合依赖，但字符串绑定任务不是现实知识 QA 的全部难度。

## 3. LV-Eval：长度、混淆事实与去记忆的分离

[LV-Eval 中文说明](https://github.com/infinigence/LVEval/blob/main/README_ZH.md) 给出 16k/32k/64k/128k/256k 五档长度，包含中英文子集，并通过 CFI 插入与支持事实相似但不直接矛盾的混淆事实，通过 KPR 替换关键词或短语减少知识泄漏，采用答案关键词相关评分。该长度体系的计数口径不可直接当作所有模型的 token 数。

**迁移示意。** 正确事实是“明川馆常规赛座位数 4,000”；混淆事实是“明川馆临时演唱会可容纳 5,200”。若问题限定常规赛，两事实可共存。再把馆名统一改为虚构名并同步改问题，是另一种干预，必须重新核对全文一致性和答案。

**分析。** CFI 与 KPR 可以单独测试：原始世界、仅 CFI、仅 KPR、二者同时。若只报告合成版本得分下降，无法区分模型是被假链干扰、失去记忆帮助，还是不熟悉替换后的语言。

## 4. LongBench 与 LongBench v2：现实长材料不是纯干扰

[LongBench 官方任务表](https://github.com/THUDM/LongBench/blob/main/LongBench/task.md) 包含多文档 QA、单文档 QA、摘要、少样本、合成和代码等任务；其中多文档 QA 收录经典英文多跳集及中文 DuReader，中文 MultiFieldQA 涉及多领域材料。这些中文任务不能直接推定每条都有显式多跳依赖。

[LongBench v2 官方仓库](https://github.com/THUDM/LongBench) 与 [ACL 2025 论文](https://aclanthology.org/2025.acl-long.183.pdf) 给出 503 条选择题、8k–2M words 的材料，六大类别为单文档 QA、多文档 QA、长上下文学习、长对话历史、代码仓库和长结构化数据理解。由有专业背景的贡献者构题，并结合自动与人工审核。words 范围不能改称 token 范围。

**可迁移题型（本调研示意）。** 对话中的早期用户偏好与后期撤销决定、文档间的版本更替、结构化记录中的同名对象，都能与多跳连接结合。但它们并非都被原作者设计成“恶意干扰攻击”，本项目需自行建立正确链与干扰链标注。

## 5. 建议采用的可控制变量

| 变量 | 为什么单独控制 | 候选操作 |
|---|---|---|
| 总长度 | 区分长文本负荷与语义陷阱。 | 固定金证据，分档加入背景。 |
| 必要证据位置 | 检测开头、中央、结尾的差异。 | 配对轮换支持段落位置。 |
| 相邻跳间距 | 检测跨远距离连接能力。 | 固定总长度，移动后继证据。 |
| 干扰数量与长度 | 多个短假链和一个长假链不等价。 | 单独记录链数、段数、token 数。 |
| 文体与来源 | 防止“合成段像噪声”成为捷径。 | 金证据和干扰使用相近文体。 |
| 顺序与重复 | 重复假事实可能形成频率偏置。 | 打乱顺序，分别重复真/假/无关事实。 |
| 问题与上下文长度 | 长题面也会引入阅读难度。 | 为语义等价题准备短/长两版本。 |

这些是本项目候选实验因素，不是所有已研究 benchmark 共同采用的固定设计。

## 6. 大规模生成的验收条件

构造同一问题的多个长度和位置变体时，应按基础样本分组划分数据，而非把不同长度随机拆到训练和测试。每个变体记录参考计数器下的长度及各被测模型实际输入长度；超窗样本要标为超窗或排除，不能把截断金证据后的错误称为逻辑抗干扰失败。

若插入背景后出现额外有效证据，预定最短链可能不再唯一；若背景包含同名角色，须说明是同一世界还是外部叙述。检查规则和指标候选见 [评测迁移报告](08_评测指标与项目迁移.md)。
