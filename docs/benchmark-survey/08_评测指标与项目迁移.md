# 08｜评测指标与项目迁移

[返回系列入口](README.md)。本文把已有评测思想转成**候选项目协议**；公式和流程若未注明原作者定义，均为本调研建议，尚未实现或运行。

**核心补充**：用户指定的多步骤评判设计已经从授权对话恢复，完整来源、定义和验证方案见 [多步骤评判与核心创新点回收](09_多步骤评判与核心创新点回收.md)。本报告保留通用指标；完整成功、路径依赖、独立部件与跨条件一致性是评测主线。

## 核心评判协议：三层评分与跨条件验证

借鉴 [DAComp 的多步骤评判](https://arxiv.org/abs/2512.04324)，恢复以下 QA 适配；它们尚未实现，不是 DAComp 的官方 QA 指标：

| 指标/协议 | 运行与判定条件 | 补足的测量问题 |
|---|---|---|
| Strict SR | 正常任务输出答案和可核验完整证明；两者同时正确才成功。 | 终点答对但桥接或证据错误。 |
| Path-CFS | 对同一合法证明检查步骤及必要祖先；断链后的依赖节点不取局部匹配信用。 | “三个实体中猜对两个”与合法依赖前缀不同。 |
| Oracle-CS | 独立运行局部子题，提供正确上游，按目标答案和支持评分。 | 局部能力和正常整题连接能力分别观察。 |
| 跨条件一致性 | 同基础题的改接、必要/无关支持删除、重排、问句切换按各自预期检验。 | 单题分数不能说明必要变化是否响应、无关变化是否保持正确。 |

线性 h 步的候选 Path-CFS 为 100×Σ(Π c_k，k≤j)/h；Oracle-CS 为独立子题成功标记的题内均值×100。完整公式、DAG 迁移、替代证明对齐、分母和评分挑战集见 [详细协议](09_多步骤评判与核心创新点回收.md)。Oracle 信息与正确前缀输入不得进入正常任务，差值不能解释成内部因果错误比例。下文 Answer+Path Joint 与 Strict SR 是同类完整成功口径，不重复作为创新贡献计数。

## 为什么不能只看最终答案

[HotpotQA](https://hotpotqa.github.io/) 同时评答案和 supporting facts；[R4C](https://aclanthology.org/2020.acl-main.602/) 进一步标注关系推导；[Compositionality Gap](https://aclanthology.org/2023.findings-emnlp.378/) 检查子问题能答对却无法组合的情况。这些指标回答不同问题，不能互相替代。

建议把模型的可观测输出限定为答案、所选证据 ID、必要的中间实体/关系，以及作答状态。评分针对外部可核验记录，不能从流畅的解释文本断言模型内部走过某条路径，也不需要收集私有思维链。

## 固定任务语义和统计单位

以基础题为独立抽样单位，以变体为嵌套观测。每题保存：

- 允许的答案集合/解释集合、合法证据集合和关系路径；
- 明确的查询条件、时间、世界版本与规则；
- 唯一可答、多答案、歧义、冲突、证据不足等状态；
- 原始题—变体对应关系及 gold 是否保持。

**多答案**可以是一个明确问题要求的成员集合；**歧义**是多个问题解释各有答案。二者不能只用同一个扁平答案列表表达。开放世界的未知也不同于显式否定。场景定义见 [场景总表](07_场景总表与中文构题配方.md)、[歧义专题](04_歧义条件与时间场景.md) 和 [规则专题](05_反向规则与知识更新.md)。

## 答案、证据和路径指标

| 指标 | 候选定义与分母 | 边界与用途 |
|---|---|---|
| Answer EM | 在可确定答案的题目中，规范化预测与任一允许的完整答案相符的比例。 | 规范化规则固定；集合任务不能“命中任一成员”就算整题对。 |
| Answer F1 | 单一短答案可用中文字符或明确分词后的重叠 P/R/F1；成员集合采用实体集合 F1。 | 明确粒度，别名先归一；“12 万”与“120000”需可验证数值规则；不能删除否定、单位或时间限定。 |
| Evidence P/R/F1 | 预测证据集合与合法参考集合比较；多个参考时按预先确定的完整参考集合匹配规则取最佳分数。 | 允许多条证明；同时报告 P 与 R，防止引用全文获得高召回；空集合、不可作答题单列。 |
| PathValid | 可答题中，输出记录能构成至少一条满足问句全部条件、得到预测答案的合法证明，且所用推导步骤均有证据/许可规则的比例。 | 验证实体身份、方向、时间、条件、跨步连接；多分支题应验证证明 DAG。它不是隐藏内部推理准确率。 |
| Answer+Path Joint | 可答题中，“答案正确且输出证明合法”的比例。 | 明确未输出证明计不通过；另外报告格式失败，避免混同推理失败。 |
| Constraint Satisfaction | 逐项校验答案/路径满足的必需条件，报告条件满足比例和全部满足率。 | 局部高分不能替代全部满足；对 S05/S12/S24 等定位错误条件。 |

证据集合匹配是 [HotpotQA 的官方评测](https://hotpotqa.github.io/) 与 [R4C 的多参考推导](https://aclanthology.org/2020.acl-main.602/) 所启发的迁移建议；这里的 PathValid 和 Joint 定义不是它们的原样评分程序。

字符 F1 对短实体较方便，但对长解释、条件绑定和数字推理不足。结构化任务优先解析为实体、数值、单位、日期、条件—结论对再评分；语义裁判仅作辅助，报告裁判版本、规则及人工审计差异。

对非空预测集合 P 和参考集合 G，精确率为 |P∩G|/|P|，召回率为 |P∩G|/|G|，F1 为其调和平均；字符答案用重复字符计数的多重集交集。两集合都空时可约定 F1=1，仅一侧空时 F1=0，但无答案题优先按状态协议评分，不并入普通可答题均值。多参考集合须先逐参考计算完整 F1，再取最大值，不能拼接不同参考的局部证据形成不存在的“满分参考”。

## 答案保持型攻击的配对指标

只对**gold 保持且题目仍有效**的配对使用以下定义。第 i 对记原始答案正确标记为 c0_i，对抗答案正确标记为 ca_i，取值 0/1。

- **原始准确率**：所有有效基础题的 c0 均值。
- **对抗准确率**：固定攻击条件下所有有效配对的 ca 均值。
- **Attack Success Rate（ASR）**：Σ[c0_i × (1 − ca_i)] / Σ[c0_i]。
- **Robust Retention**：Σ[c0_i × ca_i] / Σ[c0_i]，同一子集上等于 1 − ASR。
- **ΔAcc**：原始准确率减对抗准确率，必须来自相同基础题集合。

ASR 同时报告分子、分母和原始准确率；原始正确数为零时是 N/A，不能写 0%。原始已经错误的题目不算“被攻击成功”，但应计入绝对准确率。这些是项目候选口径，不是宣称所有来源都采用同一 ASR 定义。

每道基础题有 K 个变体时，分别报告固定单变体、随机抽取变体和预算内最坏变体的结果；选择方法与 K 不同不能直接比较。建议先对每道基础题聚合，再平均，避免生成更多变体的题目取得更高统计权重。

**Decoy Hit among Failures**：在原始正确而对抗错误的配对中，预测答案落入预先标注的诱饵答案集合的比例。分母为这些配对的失败数，零失败时 N/A。它说明错误终点与诱饵一致，**不证明模型实际经过诱饵路径**；后者需证据或中间节点记录验证。

**First Observable Invalid Hop**：在模型输出的结构化中间记录中，定位第一个违反证据、身份或查询条件的步骤。无法形成有序链、未输出记录、多分支并行错误时分别标记，不能编造唯一“第一跳”。错误类型建议包括实体、关系、条件、方向、时间、聚合和状态判断。

## 子任务诊断与组合缺口

[Compositionality Gap 论文](https://aclanthology.org/2023.findings-emnlp.378/) 的关键思想是对子题成功的条件下测主问题失败。可采用：

**CG = 全部必需子题正确且主题错误的基础题数 / 全部必需子题正确的基础题数**。

分母为零则 N/A。子题需固定分解与上下文，不能用主问题答案反向泄露子题答案。此诊断说明组合存在缺口，但独立询问子题不证明模型解主题时使用了相同步骤。

建议区分两种中间评测：给定正确前驱实体后回答下一跳，衡量局部证据读取；使用模型自己预测的前驱继续，衡量错误传播。混在一起会把第一跳错误重复计作所有后续跳错误。[MuSiQue](https://aclanthology.org/2022.tacl-1.31/) 的依赖性筛选及 [MoreHopQA](https://arxiv.org/html/2406.13397v1) 的附加推理诊断提供相关设计动机。

## 检索扩展中的分离评测

当前基准主线可采用给定证据模式；若另行开展检索扩展，参照 [MultiHop-RAG](https://arxiv.org/html/2401.15391v1) 比较以下设置，不因此要求本项目组开发检索模型或自主代理：

1. **给定证据模式**：保证 gold 全部可见，评读取、连接和抗干扰。
2. **固定检索模式**：所有模型使用同一检索结果，评证据不足与生成行为。
3. **端到端模式**：允许模型规划检索，记录查询、候选、重排、工具预算及最终回答。

候选检索指标如下。令 R_i(K) 为前 K 个实际检索单位，G_i 为第 i 题所有允许的充分证据集合：

- **Support Recall@K**：对每题计算 max_g∈G_i |R_i(K)∩g|/|g|，再对非空参考集合的题平均。
- **All-Evidence Recall@K**：存在某个 g∈G_i 被 R_i(K) 完整覆盖的题目比例。
- **MRR/MAP**：按明确的相关文档/段落标注计算，仅作检索排序补充；命中一个相关片段不等于得到完整链。
- **Conditional QA Accuracy**：在检索结果包含完整合法证据的题中计算答案准确率；与未含完整证据的组分别报告。

K 是文档数、段落数还是 chunk 数必须明说；跨 chunk 拆分、去重、文档内容更新均会影响覆盖。来源链接级 gold 不能直接当成句级 gold。不可作答题没有非空充分集合，应从上述召回分母移出，单独评状态判断。

## 歧义、拒答、反事实与方向指标

| 任务族 | 建议指标 | 关键边界 |
|---|---|---|
| 有明确成员集合的多答案题 | 完整集合准确率、集合 P/R/F1。 | 实体去重与别名归一；不通过原始字符串去重替代身份判断。 |
| 歧义题 | 解释覆盖率、解释—答案对 F1、有效澄清率。 | 解释覆盖分母为标注的合理解释；相同答案可能来自不同题意。有效澄清须区分仍影响答案的解释。 |
| 证据不足/冲突 | 状态分类混淆矩阵；拒答 precision/recall；可答题误拒答率。 | 无法确定唯一答案和没有任何可支持答案分开；答前纠正错误预设也可合规。 |
| 反事实世界 | 按新世界 gold 计算准确率、证据/路径合法率；旧世界答案侵入率。 | 旧世界答案侵入率可定义为“返回仅在旧世界有效的答案数 / 全部有效反事实题数”；新旧答案相同的题另列。 |
| 正反访问 | 正向准确率、反向准确率、成对都正确率及方向差。 | 匹配证据、跳数、答案形式；不能把上下文任务结果直接解释成训练方向的 Reversal Curse。 |
| 无效逆推 | unknown/false/true 的状态分类表现。 | 采用哪种世界假设先写清；逆命题未获许可时未知与假不可混同。 |
| 更新传播 | 被更新影响的多跳题准确率、不受影响控制题准确率、两组变化。 | 时间更新、显式编辑、现实新旧来源并非同一实验；分别定义 gold。 |

这些指标是对 [AmbigQA](https://aclanthology.org/2020.emnlp-main.466/)、[ProofWriter](https://aclanthology.org/2021.findings-acl.317/)、[CofCA](https://arxiv.org/html/2402.11924v5)、[Reversal Curse](https://arxiv.org/html/2309.12288v4) 和 [MQuAKE](https://aclanthology.org/2023.emnlp-main.971/) 场景的候选迁移，并非统一的官方复现协议。

## 实验控制与统计报告

每类干扰报告文本 token 数、文档数、干扰比例、语义相关度的构造口径、证据位置、支持间距及分支数量。字符、word、token 不混写。随机背景、相关背景、结构性假链至少有一组匹配长度的比较；否则只能说明“整体更难”，不能把下降归因于链诱导。

长上下文比较同时报告模型最大窗口、是否截断和完整 gold 可见率。对超出窗口的样本另列，不把截断丢证据当成推理失败。对于 [RULER](https://github.com/NVIDIA/RULER)、[BABILong](https://github.com/booydar/babilong) 和 [LV-Eval](https://github.com/infinigence/LVEval) 的长度设置，应按实际发行版本和具体 tokenizer 重算。

建议按基础题簇做 bootstrap 置信区间，变体随基础题整体重采样；必要时再按来源实体/模板簇分析。不能把相同基础题的多个改写视为独立样本缩窄区间。报告重复运行设置、随机种子和有效基础题数；单次运行差异不必然具有统计意义。

固定模型版本、系统提示、示例、采样参数、工具权限、重试与失败计分规则。报告调用数、输入/输出 token、检索次数、时延中位数及高分位数、费用口径。攻击用目标模型筛选时记录候选预算，并单列独立模型与保留测试集上的迁移表现。

## 从调研到构建的候选流程

| 阶段 | 应形成的产物 | 放行条件 |
|---|---|---|
| 1. 任务语义 | 场景、世界假设、状态定义、问句约束及答案规范。 | 独立读者能区分可答、歧义、冲突、缺证据。 |
| 2. 来源采集 | 原始材料、许可记录、获取时间、来源链接和版本。 | 可追溯，拟使用方式符合来源条件。 |
| 3. 基础题构建 | 证据图、问题、答案、全部合法支持及诊断子题。 | 不靠题面或单段捷径；各跳确有依赖。 |
| 4. 变体生成 | 算子、参数、随机种子、错误候选链及配对关系。 | 保持答案或变更答案的规则明确。 |
| 5. 结构和语义审查 | 图校验、答案可支持性、多解检查、独立人工抽查。 | 不以生成模型自评代替证据验证；缺陷按类型回流。 |
| 6. 小规模试验 | 多条件基线、攻击失败样本、评分审计。 | 证明测到预期机制，定位混杂因素，再决定扩量。 |
| 7. 划分与冻结 | 按来源/实体/模板等分组的版本化数据及评分协议。 | 基础题及所有变体同划分，避免跨划分近重复。 |
| 8. 盲测与错误分析 | 按场景/跳数/强度/状态的结果与置信区间。 | 不基于测试集反复调整后声称独立泛化。 |

“遮蔽某一跳后模型仍答对”是捷径筛查信号，不是严格的数学不可解证明；事实审查、图可达性和模型诊断需要结合。[MuSiQue](https://aclanthology.org/2022.tacl-1.31/) 与 [MINTQA](https://arxiv.org/html/2412.17032v3) 的方法可供机制设计参考，不能据此保证我们的生成题天然无捷径。

建议先冻结最小评分合同，再构建一批可人工核验的候选基础题与成组变体。首轮试验的目的应是验证构题和指标，而不是直接宣称“发现模型认知缺陷”。当前调研只完成文献与方案分析，**未完成数据采集、生成实现或模型评测**。
