# 06｜检索任务、知识熟悉度、领域与异构证据

[返回入口](README.md) · [资料目录](00_范围与资料目录.md)。

## 1. MultiHop-RAG：四类问题与 evidence 驱动构题

[MultiHop-RAG 构建 §3](https://arxiv.org/html/2401.15391v1) 从新闻采集开始，用 GPT-4 抽取/改写证据并标记主题和实体，以跨文档共享的 bridge-topic / bridge-entity 组织证据，再生成问题及答案，并结合模型检查和人工抽查。[作者仓库](https://github.com/yixuantt/MultiHop-RAG/) 发布 2,556 条查询，证据跨 2–4 篇文档。

| 官方 query 类型 | 构题方式 | 中文示意（合成） | 典型误导 |
|---|---|---|---|
| Inference | 用多段 evidence 共同定位答案。 | 同一赛事的两篇新闻分别说明优胜者和其所属机构，问机构。 | 相邻新闻谈另一届赛事。 |
| Comparison | 比较同主题实体的证据。 | 比较两馆在同年、同口径的参观人数。 | 拿累计人数与年度人数比较。 |
| Temporal | 从多个事件证据判断时间关系。 | 甲系统上线是在乙系统发布前还是后？ | 混淆测试、发布和正式上线时间。 |
| Null | 没有证据足以导出答案。 | 语料没有某机构两个年度的参观数据，却要求比较。 | 借相似机构数据填补缺失。 |

“多条新闻讲同一主题”只是采样候选，还需要证明问题使用了必要 evidence。原文采用“单词或实体”作为生成检查口径之一，但比较与时间题本身含判断性回答；项目应依据任务类型定义答案格式，避免把格式错当推理错。

## 2. FRAMES：组合约束与资料来源

[FRAMES 论文](https://arxiv.org/abs/2409.12941) 关注 factuality、retrieval 与 reasoning 的统一评价；[Google 官方数据页](https://huggingface.co/datasets/google/frames-benchmark) 当前显示 824 条测试样本，每题附相关 Wikipedia 链接及 reasoning_types。样例包含 Numerical reasoning、Tabular reasoning、Multiple constraints、Temporal reasoning 和 Post processing 等组合标签，不能把标签组合数量当作独立推理原语数量。

**候选示意。** 先找到某奖获奖作者，再找其第一部作品的发布日期，最后计算在另一事件日期时的年龄。干扰可保留作者正确，但换成“首版再版日”或“另一部作品”；这要求最后结果与多约束同时对齐。

**分析。** 来源链接适合检索评价，但指向页面不等于标出了唯一句级证据。若直接迁移，需要定位支持跨度并冻结页面版本；模型在闭卷时答对，不能因此声称检索成功。

## 3. MINTQA：长尾、新知识与混合链

[MINTQA 作者全文 §3](https://arxiv.org/html/2412.17032v3) 根据 Wikipedia 抽取与 Wikidata 对齐的事实及出现频率构造 popular/unpopular 链；用两个 Wikidata 快照区分旧/新增事实，构造混合链，并生成主题和子题。约束包括连通、无环、链唯一性及无图内捷径。[ACL 2026 页面](https://aclanthology.org/2026.acl-long.18/) 报告新旧知识 10,479 对、流行/长尾知识 17,887 对。

**候选场景。** 热门起点→冷门中间组织→热门城市；旧事实→新增负责人→地点；所有节点热门但关系罕见。可以对不同跳处的熟悉度进行分层，看错误是否集中在特定中间节点。

**限制。** Wikipedia 频率是作者的熟悉度代理，不是已知模型的真实训练曝光。新出现在知识库的三元组也不一定对应现实中刚发生的事实。日期或低频本身不能证明没有污染；应保留闭卷和给定证据的对照。

## 4. StrategyQA 与组合性诊断：子问题可能不在题面上

[StrategyQA 论文](https://arxiv.org/abs/2101.02235) 提供 2,780 条问题、分解和证据，要求模型发现隐式策略，以是/否回答。它的重点是确定要查什么，而非只按题面列出的实体串联。

[Compositionality Gap 论文](https://aclanthology.org/2023.findings-emnlp.378/) 测子问题都能答对时，组合题还会答错的比例，并包含 Bamboogle 等构题与搜索诊断。由此可分开测“没知识”和“组合失败”，但子题提示会改变任务，不能在最终主问题评测前泄露子题答案。

**同一研究中的两种构题流程。** [原文 §2、§3.2](https://aclanthology.org/2023.findings-emnlp.378.pdf) 的 Compositional Celebrities 先采集人物出生国家/年份，再取国家属性或对应年份事件，按 17 个模板连接两项事实。Bamboogle 则由作者阅读随机 Wikipedia 页面，手工组合关于页面主体的两项事实，形成 125 道多样化两跳题；仅在当时搜索引擎给出的 featured snippet 答案错误时收录。这是特定时间与引擎的筛选条件，不是“所有网页都不包含答案”或“今天搜索仍不能答”的证明。

**合成示意。** 世界声明某人物生活于 1800–1860 年，某通信工具 1900 年才发明；问该人物能否在有生之年使用它。两项事实与时间比较形成隐式策略。加入同名后代的人物材料可以攻击实体与时代衔接，但真实世界题可能存在概念不清或替代技术，需要审查。

## 5. QAngaroo：实体候选与专业链

[QAngaroo 官方说明](https://qangaroo.cs.ucl.ac.uk/) 将 query、多个文档与同类型候选答案结合。WikiHop 使用 Wikipedia 与 Wikidata，MedHop 使用 PubMed 摘要，要求组合药物和蛋白质反应链的信息；masked 版本用随机占位符替换候选，减少名称先验帮助。

**迁移分析。** 中文可借鉴“同类型候选”和“实体掩码”对照，比较依赖事实连接与依赖名称记忆的差别。专业机制中两个关系共享一个对象，不自动表示可传递；任何领域链都须明示可组合的规则。此处仅分析任务构造，不对药物作用作现实推断。

## 6. HybridQA 与 MultiModalQA：证据格式的连接错误

[HybridQA](https://aclanthology.org/2020.findings-emnlp.91/) 联合表格与链接文本构题：某一步从表格找实体，下一步从文本找属性，答案不能仅依赖单一形式。

[MultiModalQA](https://arxiv.org/abs/2104.06039) 从 Wikipedia 表格中的实体关联文本与图像，通过形式化组合把单模态题连接为跨模态问题，再由人改写；摘要报告 29,918 条。它是扩展参考，当前项目没有因此被自动扩大为视觉 benchmark。

**表格—文本候选示意。** 表格列“年份、作品、作者”；先筛选 2020 年作品，再去作者简介查出生地。干扰可交换行、提供另一个年份相同作品名，或放另一作者的简介。必须保留表头、行键和链接实体 ID，否则序列化过程自己就会破坏正确证据。

## 7. ComplexWebQuestions：逻辑形式先行，再人工自然化

[ComplexWebQuestions 原文 §4](https://aclanthology.org/N18-1059.pdf) 扩展 WebQuestionsSP 的 SPARQL 查询，覆盖 composition、conjunction、superlative、comparative，生成机器问题后由众包自然化；报告 34,689 对。原框架在网页作答时，并非对所有最高级/比较题都显式枚举聚合，而会依靠网页直接表述；因此复杂问题标签本身不证明一定走过多跳。

**中文构题配方。** 先构造可执行的 join/交集/极值查询，计算答案，再改写成自然语言；最后检查改写是否保留所有条件。这适合保证大规模真值，但固定模板仍可能泄漏题型和答案，应留出关系组合与语言模板。

## 8. 对项目场景覆盖的建议

场景标签宜同时记录事实/架空、公开知识/封闭业务知识、一般/专业领域、文本/表格/其他证据形式、热门/长尾/新增事实。业务材料可以来自合成组织世界，不必真实采集私人资料。检索失败和推理失败分别测，建议先做完整证据输入，再增加受控检索；具体协议见 [评测迁移报告](08_评测指标与项目迁移.md)。
