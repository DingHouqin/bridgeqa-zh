### 3.1 本次已经复核的两类反例

**问题盲结构策略。** 只解析公开材料的节点连接，寻找唯一入度大于1的节点，再沿唯一后继走到终点。不读取问题、ID、root、条件、hop或gold。全部预测先生成，事后才由评测端分组：内部桥改接条件答案命中11/11，完整及重排的12个可答条件命中0/12。主智能体独立复核关键计数。

这说明旧改接条件的答案层存在结构捷径。它没有提交完整证明，不等于通过Strict SR，不是评分器漏洞证明，也不是LLM实际使用该策略的证据。

**marker-only策略。** 识别“本句未提供关系事实。”或“本题未提供事实材料。”后输出合法空拒答，否则报错。学术对手通过旧评分API实跑：不足条件通过23/23，总合同root宏分0.4。每root五类条件等权，后两类通过，因此是2/5；不是23/46微平均，更不是40%的多跳能力。

这些反例可以作为新研究的历史起点，但不能替代新来源、新条件和独立验证。原实现的完整合同通过，不等于各条件都测到了预期构念。

## 4. 研究对象与可支持的主张

建议研究问题是：在明确的中文材料与回答规则下，题目是否需要预期的证据组合；对抗或干预是否保持任务合法性；评分是否能区分合法回答、证据不足与构造捷径。

| 层次 | 要检查什么 | 结论边界 |
|---|---|---|
| 材料内语义必要性 | 最短合法证明、替代路径、关系与事件限定 | 只相对于给定材料和明确规则，不等于模型不能凭知识答出。 |
| 可观察输出正确性 | 答案、支持和证明是否形成合法整体 | 证明可能是事后生成；不能据此推断内部计算顺序。 |
| 可观察行为依赖 | 必要变化时更新，无关变化时稳定，缺必要信息时不强答 | 需要实际输出和控制条件；仍需排除结构、位置和模板解释。 |
| 内部推理机制 | 内部是否按指定路径生成、错误如何传播 | 当前计划不以识别内部机制为承诺；自由解释、Oracle差值均不足以证明。 |

可检验的主贡献候选是“面向不同多跳场景的构建与有效性审查协议”。是否构成创新，要看发现的风险、控制方案及新数据验证，不靠中文、题量、匿名化或完整路径这几个部件本身获得首创性。

## 6. 场景体系建议：四个正交维度

| 维度 | 问题 | 候选标签 |
|---|---|---|
| 推理结构 | 正确回答需要怎样组合信息？ | 线性组合、分支比较、多条件交集、规则推断、事件连接、时间约束、聚合。 |
| 挑战机制 | 什么诱导证据选择／组合出错？ | 冗余、错误桥接、关系混淆、实体混淆、时间错配、方向误读、位置或结构线索。 |
| 答案状态 | 材料允许确定什么？ | 唯一可答、集合答案可确定、证据不足、问题歧义、冲突未解决。 |
| 对照预期 | 改动后应发生什么？ | 保持、按映射转换、更新、不作唯一断言、接受其他合法证明。 |

例如“三跳线性组合＋同名人物混淆＋唯一可答＋加入干扰后保持”，与“双支路比较＋时间错配＋唯一可答＋必要时间改变后更新”可以分别统计。

反向是关系方向；歧义是答案状态；冗余是证据条件。不能将三者当成同一层互斥类别。用户原举例的五类都可保留，但应放入相应维度。

跳数建议同时记录路径／分支深度、支持事实数和操作数。分支比较的四条事实不应未经定义直接称四跳。图只是标注表示，关系和时间语义仍需人工确认。

## 7. 可构建场景及操作性边界

以下例子仅为设计示意，未作为真实来源事实或正式样本。

### 7.1 优先覆盖的基础任务

1. **线性关系组合**：甲所属组织的负责人，其出生地在哪里？检查每一步是否必要、是否有短路和已知人物线索。
2. **分支／桥接比较**：找到两个事件的负责人，再比较其任职时间。两条支路都需必要，不能只读一边即可判定。
3. **多条件交集**：谁同时参加事件一并担任事件二的指定角色？提供只符合单个条件的候选；检查交集答案及候选范围。
4. **事件与角色辨析**：区分提议者、执行者、受益者，或者通过两个事件连接实体。共同出现不等于角色相同。
5. **时间／阶段限定**：在一次转变之前，甲隶属组织的负责人是谁？时间可以是相对事件顺序；不得凭题外知识补足材料。
6. **反向关系组合**：由“甲任命乙、乙管理丙”反向寻找对应任命者。一对多时必须加合法限定或要求集合，不应暗中选一个。
7. **隐式组合关系**：问题使用外祖父等组合关系，而材料给出基础关系。需要明确组合规则是否属于许可知识。
8. **聚合／排序**：先按关系条件筛选，再计数或确定最早者。只有材料覆盖完整范围时，才能对数量、最高级和“所有”作可靠标注。

### 7.2 可施加的挑战

| 挑战 | 设计思路 | 语义约束 |
|---|---|---|
| 冗余与高重合文本 | 共享人物、主题或关键词，但不参加证明 | 不能意外新增短路；普通对照应控制长度和材料预算。 |
| 错误中间实体 | 同名、近名或候选身份被错接 | 正确身份区分依据必须在材料里。 |
| 错误事件／阶段 | 同一人物另一个事件的关系被接入 | 事件或时间限定明确，不能依靠未提供常识。 |
| 误导性关联 | 共事、共现、相邻等被误当目标关系 | 写明需要的关系；关联事实可以真，但不构成目标证明。 |
| 方向混淆 | 将任命与被任命、管理与被管理混用 | 不把逆关系当原关系逻辑逆命题；检查基数。 |
| 位置与形式线索 | 移动支持、变更句槽或等价表达 | 语义不变；文档／句子编号和参考同步更新。 |

虚假中间线索不能等于任意加入与gold矛盾的同等可信陈述。如果没有来源层级或任务真值规则，材料可能变成冲突题，不能仍以原答案作为唯一gold。优先做可被身份、事件或时间限定排除的伪连接。

### 7.3 专项答案状态

歧义题至少需要两种合理解释及不同答案，并分别提供支持；消歧条件应改变相应限定。集合答案多不等于问题歧义。证据不足表示给定材料不能支持回答，也不等于现实世界没有答案。冲突无法按规则解决时应标为未解决，不得暗中偏好某来源。

来源限定可以做专项，例如“按来源甲／截至时间t”。若研究新旧事实、来源可信度，规则必须提前明确。因果题只在来源与许可规则确实支持因果时构建，事件先后或相关不能自动升级为因果。

## 8. 最值得深化的有效性诊断

### 8.1 必要、无关与替代支持删除

同一题分别删除无关材料、某条参考上的证据、以及所有合法证明所需的支持。三者可能对应保持、仍可走替代路径、证据不足。不能把“在参考里”直接当成“对任务必要”。有多条合法证明时，单边删除未必不可答，应检查最小证据集合或必要切断集合。

可答与不足条件采用相同的呈现策略，防止固定marker直接给标签。缺失条件还应检查句数、长度和格式是否泄露答案状态。

### 8.2 同一材料，切换问题起点

保持材料与图不变，改变起点、事件或询问对象，选取预期答案不同的配对。问题盲扫描结构难以通过此条件。起点应在实体类型和呈现上可比较，避免特殊标签替代问题理解。

### 8.3 答案相同，所需支持不同

例如 `A→B→Z` 与 `C→D→Z`，两题答案相同，但从不同起点出发。单看答案无法区分正确依据；提交支持需要满足指定问题。同时必须接受确实合法的其他路径，不强制唯一措辞。

### 8.4 分布式冗余与事实层充分性

同一事实在不同位置以不同表达支持：删一处保持，删全部支持后不足，删等长无关内容保持。此场景能发现漏标替代支持、文本位置依赖和把句子ID当事实的误差。

### 8.5 语义变化与表面变化

等价改写、重排和一致实体映射应保持或按映射转换；必要关系变化应更新。匿名子集中可以交换两条同层边，使入度／出度保持，减少旧单边改接的汇合线索。双边交换是未来协议，不能冒称旧单边构造已做到。

这些设计也可能引入新线索。应先运行问题盲、marker、位置、终点角色等简单探针，并在未用于调整的新题上验证。探针失败只说明已检验的策略失效，不能证明所有捷径消失。

## 9. 数据规模：先试场景，再配额

此前提出的24个基础题被用户认为太少；后续讨论过200个基础题、约600条条件记录。200可以作为预算讨论锚点，但不是已批准的最低规模或必须完成承诺。最新调研后，“五类各40题”的固定分配应撤回。

建议先对候选结构和挑战做少量原型，检查来源供给、类别区分、条件合法性和人工耗时，再确定正式场景矩阵及题量。优先有文献和材料支撑的核心场景，不做所有维度的笛卡尔积。

| 计数对象 | 应如何解释 |
|---|---|
| 基础题 | 实质不同的事实链／目标；单纯换名、改写不算新增基础题。 |
| 题族 | 同一基础题及其问题、材料和干预变体。 |
| 条件记录 | 可答／攻击／删除等观测，通常相关，不能当独立题。 |
| 来源／事实簇 | 共享事件、证据、事实和近重复结构的分组，影响划分与统计。 |

分支比较、交集、事件／时间限定可优先补足旧线性链；匿名诊断建议做受控子集，不必给所有自然题复制全部条件。歧义、冲突、集合答案分别报告，不强行纳入同一种攻击成功率。

## 10. 构建流程与应同步积累的说明

1. 确认领域、来源版本、使用条件和任务世界规则。
2. AI提出候选事实、题目和条件；人定位原文，纠正关系、指代与事件限定。
3. 标注合法证明、最短证明依据和替代支持；没有可靠材料的候选修订或拒收。
4. 按场景施加单一主要挑战；记录改变和预期响应，检查是否意外改变真值。
5. 交叉人工审核、处理分歧；运行结构和格式检查。AI意见只是线索。
6. 按来源／事实簇划分；相关表示、变体和近重复题不能跨划分。
7. 在开发部分寻找捷径并修订协议；另留不用于调参和条件选择的验证部分。
8. 冻结版本，复核评分与统计，形成可追溯结果。

每批题同步记录下列内容，不能终期靠记忆补写：

| 说明 | 最小记录内容 |
|---|---|
| 来源 | 名称、版本、获取与使用条件、原文位置、文本派生与转换。 |
| 构建 | 候选来源、AI参与范围、人工改动、审核和拒收理由。 |
| 设计 | 结构、主挑战、答案状态、必要关系、条件目的与预期变化。 |
| 陷阱 | 诱导的具体错误步骤、错误候选、材料内排除依据。 |
| 标注 | 答案、别名、事件／时间限定、支持、关系方向、合法证明、歧义解释。 |
| 统计 | 计数单位、来源簇、分歧、修订、缺字段、评分争议及失败类别。 |

保留拒收候选和理由是研究证据，但不必为每一轮讨论生成独立文件。实际落盘格式和目录待新设计决定，应尽量少而清晰。

## 11. 人与AI的角色、每周组织

四人交叉参与完整小批构建，不长期按研究、代码、标注、报告四块隔离。可轮换双人搭档，每题另分配两位非构题者审阅；有实质分歧由第四人加入处理。不能把构题者自查或AI多次回答算独立人工审核。

AI可辅助候选提取、干扰草稿、字段整理、替代解释建议、检查程序和统计汇总。人负责来源核实、任务语义、合法性、分歧、正式入集及报告主张。AI发现不了问题不构成验收。

每周任务建议明确：输入、完整小批产物、构题与审阅分配、依赖、可判定验收和未解决项。工具／规范小任务由成员轮换，避免某人只写代码、不理解题目。

每周约30分钟同步：已验收及争议题，共性问题与规范更新，覆盖和耗时偏差，下一周任务。可以参考每人2小时主任务、1小时审核、0.5小时同步；这只是3.5小时／周的预算示例。

## 12. 可用的验收建议与不能设置的模糊门槛

| 对象 | 可判断的条件 |
|---|---|
| 来源与派生 | 指定原文可定位，版本与记录一致，派生能对应原文。 |
| 可答题 | 给定材料支持答案；每步关系与限定有依据；未解决替代答案不能放行。 |
| 跳数 | 按已定义单位计算；发现更短合法证明则修订或拒收。 |
| 干扰 | 可指出为什么不构成合法证明；原真值不被意外改变。 |
| 歧义 | 至少两种合理解释及不同受支持答案；对应消歧条件可区分。 |
| 反向 | 方向与关系语义正确；唯一或集合答案规则明确。 |
| 入集 | 两位非构题者审核；实质分歧解决；必填记录完整。 |
| 评分 | 对人工确认的合法／非法案例结果符合规范；合法替代证明不能仅因未列单一参考被误罚。 |
| 工具 | 预设检查案例得到预期结果；异常不被静默吞掉。 |

“足够难”“干扰合理”“创新性强”“已消除全部捷径”不能作为不明确的放行标准。短路搜索和人工核验只能在已规定材料与规则范围内形成证据，不能宣布对所有可能推理穷尽证明。

这些验收建议本身也需团队确认；报告没有替新项目冻结规则。

## 13. 困难样本与统计分析

分别记录构建困难、审核困难和作答困难。没有答题输出，不能凭题长、跳数或AI评价把题称为模型困难样本。

建议按结构、挑战、答案状态、路径深度、支持数、材料长度和来源簇统计。报告审核分歧的类型和解决方式，不预设任意一致性阈值。困难案例至少区分：来源缺依据、指代／阶段不清、替代证明、干扰引入新答案、逆关系多解、结构／marker捷径、评分漏接合法证明。

若有固定系统输出，分别报告答案、支持、合法证明和跨条件响应；必要变化敏感性与无关变化稳定性并列。不能让始终拒答或始终相同答案获得看似良好的单项成绩。可答、集合、歧义、缺证据和冲突条件不强行混成一个解释不清的总分。

统计单位优先基础题／题族，并考虑来源簇。变体不能当独立样本；少量簇不足以保证稳定置信区间或显著性。困难题选择不能只依据某个系统失败后筛选，再用同一批题宣称普遍难度。

## 14. 十二周安排的参考框架

总人力约144–240小时。题量与条件数量应由前期计时校准，不能假定每人始终投入5小时，也不能用减少关键人工审查维持表面题量。

| 时间 | 并行任务 | 审查产物 |
|---|---|---|
| 第1周 | 场景原型、来源摸底、材料规则、记录真实耗时 | 候选场景边界、可用来源与工作量估算。 |
| 第2–3周 | 小批构建与交叉审核，同时更新规范、复现旧捷径 | 经过审核的多场景开发题；拒收／修订记录；明确对照。 |
| 第4周中期 | 检查覆盖、标注、有效性和规模可行性 | 团队审查并决定后续范围，不能只以记录条数验收。 |
| 第5–6周 | 按中期结果扩建；比较、交集、事件／时间条件；诊断子集 | 可复用规范与新事实簇；干预合法性证据。 |
| 第7–8周 | 继续构建、处理替代证明、检查划分和新捷径 | 大部分目标题、交叉审核及待解决项。 |
| 第9周 | 解决剩余争议，冻结数据与评分 | 可追溯版本；开发与验证用途明确。 |
| 第10周 | 冻结探针验证；如有协作输出则评分；分析跨条件结果 | 计数、失败机制和替代解释。 |
| 第11周 | 独立复现、抽查与说明整理 | 来源、流程、陷阱、标注、困难统计与局限。 |
| 第12周终期 | 审查主张与证据，修订交付 | 结论、数据和版本一致，可复核。 |

中期应能展示场景区分、至少几个完整题族、人工发现与修复的问题、可复现的风险与对照，并用实际耗时审查规模。终期重点是语义与干预可信、已知风险受到检验、评分可复核、结论边界准确，而非必须得到提升或显著差异。

用于调整方案的验证题应转为开发资料，另留最终验证；冻结后修正标注错误要保留记录并说明结果影响，不只重跑有利部分。

## 15. 创新方向、可证伪条件与范围取舍

优先深化四个问题：必要证据与参考证据是否相同；回答是否依赖具体问题；评分是否覆盖合法证明；语义干预是否与表面线索分离。

可以成立的工程贡献是可追溯构建、人工审核、受控条件和可复现审查。待验证的方法贡献是场景化有效性协议是否识别了传统答案指标遗漏的问题，以及控制是否在新题上有效。

下列结果应降低或改变主张：修正后浅层策略仍稳定成功；删除所谓必要边仍有合法回答；合法证明被误罚；效果来自长度、格式或固定marker；新来源验证不复现；跨条件诊断不提供额外信息。负面结果可以交付，但必须改变解释，不能继续宣称方法已经有效。

暂不必承诺联网检索、工具使用、多模态、模型优化、全领域覆盖、复杂因果推断和完整知识记忆归因。场景扩展应服务测量问题，不按名字数量追求丰富。

## 16. 重新设计时需要团队审查的事项

1. 主贡献的准确问题表述及任务世界规则。
2. 领域、来源、使用条件及可持续的候选供给。
3. 基础结构、挑战、答案状态及其允许组合。
4. 题量、跳数／事实数定义、条件数与审核成本。
5. 歧义、集合、缺证据和冲突的参考与评分形式。
6. 来源／事实簇划分和最终验证用途。
7. 交叉审阅、争议处理与AI辅助披露。
8. 是否需要跨组取得固定系统输出，以及未取得时的结论范围。
9. 中期／终期日期、最小交付及退出条件。
10. 最小必要文件结构，避免再次产生大量无用途记录。

以上清单不是已决策事项，也不要求自动执行。报告作为重新设计的输入，不能自动生成新计划、子智能体流程或批准题量。
