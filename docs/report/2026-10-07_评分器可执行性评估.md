# 当前候选集是否足以构建完整评分器

评估日期：2026-10-07。范围为 [候选集](../../data/pilot_literature_history_v0/README.md)、[多步骤评判协议](../benchmark-survey/09_多步骤评判与核心创新点回收.md) 和 [构建器](../../src/pilot_literature_history_v0/build_pilot.py)。未读取其他分支或使用参考报告作决策。

## 结论

**不足以直接构建完整、可复现的多步骤评分器。** 已有标注可以支撑精确答案、状态、材料 ID 和结构化 gold 的计算；核心缺口是如何把模型实际提交的证明可靠地对齐到 gold，并判断关系、操作、依赖与合理拒答。只比终点的程序不能满足完整成功、依赖传播与协议有效性目标。本次不把部分指标实现冒称完整评分器。

无需重新采集全部资料或重做题库。需要补版本化输出合同、语义判定与特殊状态规则、聚合口径及评分挑战集。其中工程规则可以设计实现；合理拒答、语义等价和评分误罚还需要新增标注与独立裁定。

## 已具备的基础

- [主任务 gold](../../data/pilot_literature_history_v0/benchmark.jsonl) 有128条：98条可答、8条歧义、22条材料不足；含事实、查询、材料映射、参考 DAG、实体映射、场景和家族。
- 16条记录有多份证明；其中歧义题的各解释不能当作同一可答题的互换路径。另有重复支持形成的合法替代证明。
- 共11种操作：查找、别名消解、比较、范围枚举、完整名录读取、成员判断、页数读取、求和、开放世界规则判断、假设及规则应用。
- 108条记录有实际比较对象和变更描述；不等于108个同类型独立攻击对。
- [主输入](../../data/pilot_literature_history_v0/inputs.jsonl) 与 [节点输入](../../data/pilot_literature_history_v0/oracle_inputs.jsonl) 已独立导出；[节点 gold](../../data/pilot_literature_history_v0/oracle_gold.jsonl) 有58条目标答案和支持材料。
- [构建检查](../../workspace/pilot_literature_history_v0/validation.json) 验证结构和重算一致性，没有验证对实际提交的误接受、误拒绝。

固定规范化和结果包装后，答案 EM、状态准确率、材料 ID 合法性、独立节点答案与支持匹配均可先实现。证据集合 F1 也可实现，但须先定参考选择、额外引用和空集合规则；它不能证明材料被正确理解。

## 为什么不能简单比答案和步骤关键词

题号 Q1e7d33f27419 的参考要求：项梁通过“拘捕求书之人”到曹咎，再通过“该信收信人”到司马欣，最后得到官署所在地栎阳，详见 [主任务 gold](../../data/pilot_literature_history_v0/benchmark.jsonl)。

提交“答案栎阳；项梁的父亲是曹咎，曹咎的朋友是司马欣，司马欣的官署在栎阳”，即使引用全部正确材料，仍是错误证明。实体序列匹配会误接受，强制复制参考措辞则会误拒绝合法表述。

C06 的目录表提供多个作者与页数，引用表格 ID 不能证明取对行；错误作者与另一本书的页数组合，可能碰巧得到25。必须核验逐操作输入与支持。

参考链局部合法性 [1,0,1] 的 Path-CFS 应为1/3，而非2/3；并行 DAG 的独立支路则不能因为另一支路错而全部失分。现有 gold 提供依赖图，缺的是可信的局部合法性判断。

## 最短补齐顺序

1. 固定 pilot 评分版本与结构化输出合同，覆盖当前11种操作；步骤自行编号，不向模型提供 gold 节点、答案或正确上游。明确自由文本的支持与复核边界。
2. 补解释对应、有效澄清、缺证 rubric、答案别名和数值规则，审核表格、时间、规则及假设语义。
3. 冻结答案、状态、Support F1、Strict SR、Path-CFS、Oracle-CS、首次断链、配对和家族成功的选择规则、适用范围与分母。正确前缀干预尚无输入与 gold，暂不发布 Prefix-k；现有 Oracle 仍仅覆盖基础查找节点。
4. 实现解析、局部判定、对齐、DAG传播、特殊状态、配对聚合和报告，用独立裁定的挑战提交验证。构建器重算 gold 不能代替评分器挑战测试。

补齐后可以实现覆盖当前候选集的评分器。程序可执行与测量效度分别报告：独立人工审核、模型实跑、正式划分及统计外推仍需后续验证，但它们不全部是写评分代码的前置条件。
