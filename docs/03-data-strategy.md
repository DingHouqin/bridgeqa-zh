# 领域与数据策略

比例均按独立 seed 计。语言排列和攻击扩增不增加独立题量；所有变体继承同一 seed_id 与 split。

## 来源层

1. `translated_seed`：翻译 MuSiQue-Ans、HotpotQA 或 2Wiki 的题与上下文，保存原版本/ID/许可/原文/翻译记录。启动可多用，期末建议 20–30%；单列参照结果。主隐藏结论优先 native_zh。英语原题公开，不能保证语义未被模型见过。
2. `native_zh`：先找中文原文和事实链，再人工写中文问题。英文证据变体可能是翻译，但 seed 来源仍为 native_zh。
3. `fictional_fixture`：内部例子、接口检查或明确的合成诊断，永不冒充真实原生数据，不进入主 benchmark 数量和结论。

起步优先统一一种英文来源。MuSiQue 有子问题与段落支持信息，句级证据需补标；Hotpot 有支持句；2Wiki 有路径结构。不能假设三者标注单位相同。

## 领域选择

候选主领域为文化遗产/博物馆/作品/人物，次领域为高校/研究机构/人物。最终选择需检验：可追溯原文、稳定事实、唯一关系、两到四跳自然问题、双语别名与资料、采集和分发条件、B 组可用知识覆盖。

先各制作 20–30 道题，记录每题找证据与审核耗时、捷径率、多答案率和双语等义率。不要先按兴趣宣告大量题目可生成。主次领域都在 dev 和 test 中有题；领域不能与某一种攻击或某个跳数绑定。

## 跳数与规模

建议 2/3/4 跳 25/60/15%，以 300 seeds 的规划例子对应 75/180/45；300 是容量估算示例，不是承诺或硬门槛。三跳主集优先比较 target_hop，四跳主做描述性压力测试。

正式规模按 `有效种子数 × 每题构建/两人审核时间 + 双语审核时间 + 实验预算` 决定。数量不足时先收缩扩展因子，保留可审核的主实验。

## 切分与污染

先按 seed 和相关实体/文档簇切分，再生成攻击和翻译。近重复问题、同源单跳组件、共享关键证据、原题不同语言版不能跨 split。大实体簇会造成比例偏移，记录折衷而不追求完美百分比。

记录 benchmark 原始训练/dev/test 身份；不能用公开英语答案支撑“全新 hidden 知识”主张。新中文事实也不能证明无预训练污染，应以 source 记录、记忆诊断与证据审核说明限制。
