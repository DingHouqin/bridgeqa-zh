# 项目意义、贡献定位与课程证据

日期：2026-09-30。本文是项目定位与验收约定；真实题库、模型结果和贡献效果均尚未验证。范围与配额以 [设计草案](17-benchmark-spec-proposal.md) 和 [建议配置](../configs/benchmark-spec.proposal.json) 为准。

## 1. Benchmark 的意义与本项目的问题

Benchmark 把一种能力转化为可重复的任务、输入条件与判定规则，使团队能够公平比较方法、诊断失败并积累可复用材料。

本项目的问题是：模型能否从中文候选材料中选择正确证据，连接必要关系，并在有干扰时仍给出有依据的答案？

观察对象包括答案、支持句、提交证明及独立干预后的结果。提交证明受支持，不等于已证明模型内部实际沿该路径思考。

| 质量要求 | 项目验收证据 |
|---|---|
| 测量有效性 | 必要依赖、最短有效证明、捷径与删证据检查记录 |
| 标注可靠性 | 原文、出处、限定、等价答案、备选完整证明及独立复核 |
| 区分与诊断 | 普通/攻击结果、错误类型、可观察路径及独立上游诊断 |
| 实验控制 | 文档、位置、长度、预算和模型条件的匹配与差异记录 |
| 覆盖与边界 | 来源、领域、跳数、攻击分布；开发/隐藏分别报告 |
| 可复现性 | 冻结的数据、代码、规则、提示、模型 revision 与运行记录 |
| 实际用途 | B 组依据诊断提出优化，并在冻结隐藏集检验 |

40–60 道核心种子主要支持课程中的受控比较与案例分析。变体不是新的独立种子；小组间的小差异、多重切片和跨领域推广应受样本量约束。数据接收不以“某个模型必须答错”或达到目标 Drop 为条件。

## 2. 对外定位与贡献状态

目前可以使用的项目定位：

> 本项目拟构建具有可追溯中文来源和必要关系链的多跳问答评测，设计保持任务真值的匹配干扰，并结合答案、证据、完整路径与正确上游诊断，分析模型及优化方法在干扰条件下的表现。

在报告中用词随证据升级：

| 状态 | 可用表述 | 升级依据 |
|---|---|---|
| planned | 拟构建、计划比较、待检验 | 已有定义与实验计划 |
| implemented | 已实现、已构建若干审核题 | 可检查代码、真实审核数据与版本 |
| observed | 在本数据/设置下观察到 | 实际运行、分母、指标、成本与审计 |
| supported | 结果支持某个有限范围的结论 | 匹配比较、错误核验、统计与替代解释说明 |

实施成功不自动证明效果。当前贡献状态为 planned；已有格式夹具和最小评分工具需单独说明。不得把“中文、三四跳、攻击、逐跳评分、LLM 构题”各自写成首创。

## 3. 与已有工作的关系

以下仅根据已核对的论文说明关联；不据此断言其他数据集缺少所有本项目功能，也不宣称完成全面新颖性检索。

| 相关工作 | 已有能力/方法 | 本项目拟增加的具体价值 |
|---|---|---|
| [MuSiQue](https://aclanthology.org/2022.tacl-1.31/) | 组合连接的单跳问题、2–4 跳、捷径过滤 | 在可追溯中文来源中核验必要链并评测匹配干扰 |
| [HotpotQA 对抗评测](https://aclanthology.org/P19-1262/) | 保持原答案的对抗文档与捷径诊断 | 将匹配不变量、攻击有效性和差异记录纳入本项目协议 |
| [2WikiMultiHopQA](https://aclanthology.org/2020.coling-main.580/) | 结构化/文本构题与推理路径 | 答案、证据、完整证明与正确上游条件的联合诊断 |
| [推理链攻击，CCL 2023](https://aclanthology.org/2023.ccl-1.1/) | 依据推理链与类型构造干扰、对抗增强 | 中文来源审核、配对控制与 B 组证据选择/组合优化的闭环 |
| [CofCA](https://arxiv.org/abs/2402.11924) | 逐步反事实多跳评测 | 本主实验维持原任务真值；反事实/歧义另立协议 |
| [CCMOR](https://arxiv.org/abs/2510.08800) | 中文事实链、LLM 构题、人工验证 | Source Schema 贯通构题、配对、审核、评分，并测实际质量/成本 |
| [DAComp](https://arxiv.org/pdf/2512.04324) | 正确上游下的部件评分、依赖失败与成功指标 | 适配中文 QA 的 Strict SR、Path-CFS 与独立 Oracle-CS；保留条件差异 |

不同数据集上的分数不能直接证明本项目更好。若使用已有英文题的中文改编作参考，先匹配任务、模型、输入和预算，并保留改编与来源标签；该比较仍不等于证明中文或某领域的因果影响。

## 4. 三项核心贡献与一项可选贡献

### C1：原生中文来源中的可审计必要链

- **拟贡献**：真实中文材料中的实体身份、简称/历史名、角色关系及时间限定，形成有证据的必要链。
- **验收材料**：出处、逐边引句、限定、合法完整证明、捷径检查及独立审核。
- **可检验结果**：合格率、拒绝原因、相关标签的真实失败案例；有足够样本才作类别比较。
- **边界**：中文本身非首创；原生来源也不保证模型从未见过。单领域结果限定于本材料与模型设置。

### C2：保持真值的严格配对攻击

- **拟贡献**：同题固定 gold、数量、位置、来源呈现和近似长度，控制错误桥接/冗余/关系混淆等干扰。
- **验收材料**：配对检查、文本差异、实际 token 差及人工攻击合法性审核。
- **可检验结果**：普通/攻击的 Answer EM、Strict SR、Drop、ASR 与双条件成功率；辅助机制用共同种子子集比较。
- **边界**：新答案或不可消解冲突会改变任务；必须拒收、修正或归入独立挑战。仅控制这些变量不等于识别模型内部的因果机制。

### C3：答案、证明与独立上游诊断

- **拟贡献**：区分答对、选对证据、完整证明成立，以及正确上游下的单跳能力。
- **验收材料**：程序判定规则、人工核验案例、独立单跳子问题与干预运行。
- **可检验结果**：答案正确但完整证明失败的数量；首次提交证明错误；正确上游/前缀后的表现；B0/B1 在相同条件下的变化。
- **边界**：Path-CFS 评价提交证明，Oracle-CS 是独立条件；不能把两者差值视作内部错误传播比例。新增指标尚待实现。

### C4：Schema 驱动构题的质量与成本（可选）

- **拟贡献**：统一源事实、题目蓝图、攻击不变量与评分要求，比较其对合格率和审核成本的实际作用。
- **验收材料**：相同事实包与模型条件下的构题对照、匿名审核、拒绝/修订记录、耗时与一次性准备成本。
- **可检验结果**：首轮合格率、语义缺陷类型、每道最终合格题的人工分钟和实际模型成本。
- **边界**：有 Schema 不自动提高 judge 准确率；没有专门裁判校准实验就不声称该效果。优先完成 C1–C3。

具体比较见 [贡献验证计划](../experiments/plans/contribution-validation.md)。状态和材料路径在 [贡献证据登记表](../reports/contribution-evidence.template.csv) 登记；真实隐藏材料只保存到私有目录。

## 5. 如何形成课程可检查的成果

课程明确要求任务/数据/指标、构建过程、困难与陷阱、普通/对抗比较、失败与优化分析、展示及完整交付；权重为期中 30%、期末 40%、材料 30%，见 [课程要求](14-course-requirements.md)。下面是本项目对这些要求的落实，不是教师额外公布的评分细则，不承诺分数。

| 阶段 | 建议拿出的材料 | 对应贡献与能力 |
|---|---|---|
| 期中 | 相关工作对照、Schema、真实审核事实链、攻击对、可运行接口和已有评分 | C1/C2；问题定义、数据设计、工程实施 |
| 期末 | 冻结后的普通/攻击与 B0/B1 结果，答案/证明对照、干预及核验案例 | C2/C3；受控实验、诊断、A/B 协作 |
| 私有交付 | 数据、出处、审核、split、评分程序、运行记录、成本及 AI/成员贡献 | C1–C3；可信、完整、可复现 |
| 可选补充 | 构题对照与实际审核成本 | C4；有限人力下的质量与效率验证 |

课程可能希望训练完整的问题定义、数据评测、模型优化、实验分析和合作表达能力。这是依据交付要求的推断，不是教师公布的教学目标原文。

若 B 组优化没有明显提升，应报告真实结果和条件，分析已修复/未修复失败、成本及样本限制。不得为了显著下降或提升选择隐藏题。可靠的负结果仍可形成可检查的工作成果。

## 6. 建议的成果链

```text
研究问题
  → 来源与必要链（C1）
  → 匹配攻击与语义审核（C2）
  → 冻结普通/对抗评测
  → 答案、证据、路径及上游诊断（C3）
  → B 组优化与有限范围结论
  → 可复现私有交付
```

主线保持纯中文、单领域与固定候选。中英、多领域、固定语料检索以及 C4 是扩展，不为展示贡献数量而自动加入必做任务。
