# A/B 组接口协议 v0.1

状态：供双方讨论，尚未确认。B 组联系人、模型与资源待填；本文件不代表已向 B 组发出消息。

## 双方职责

A：任务定义、数据采集、攻击生成、审核、切分、评测代码和缺陷分析。B：模型调研、算法实现、优化与训练日志。双方均可提出改进建议。

## 输入与输出

模型输入仅包含 `sample_id`、question、question_language、documents（doc_id/title/language/sentences）以及 task instruction。不得带 gold、路径、attack、origin/source_id 等可泄漏标签信息。真实来源元数据是否允许用于可靠性判断必须事先定义。

输出含 sample_id、answer（text/canonical_id）、support（doc_id/sent_id）、可选 submitted_steps（hop/head/relation/tail）、status。canonical ID 映射在评测端完成也可，不能给隐藏答案候选映射泄漏。

格式失败记错误并统计；不得 silent repair 后称模型原始输出有效。若使用约束解码，记录方法和影响。

## 数据使用

公开开发可给输入与 gold，并明确是否允许 B 组训练/调参。各领域、2/3/4 跳与各 task 都有公开例子。隐藏输入通过固定评测 runner 或最终批量执行提供；隐藏 gold/来源种子映射不提前交 B。

A 在独立的开发模型上开发攻击，记录是否经模型筛选。评估未知模型与 B 最终模型，不能在隐藏结果后选择只成功的攻击。公开 taxonomy，隐藏具体题和模板参数属于课程项目方法，不是保密承诺。
