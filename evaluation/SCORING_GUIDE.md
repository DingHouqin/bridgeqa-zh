# 评分器与过程评价说明

更新：2026-10-27。在线入口：[评分器](https://dinghouqin.github.io/bridgeqa-zh/#/scoring)、[逐题表现](https://dinghouqin.github.io/bridgeqa-zh/#/results)、[最新题目](https://dinghouqin.github.io/bridgeqa-zh/#/latest)。本说明对应现有冻结的[证据绑定 pass 评分器 v15](pass_metrics_v15/README.md)及其在[Luna / Sol v16 开发实验](../model-testing/luna_sol_v18_publication.md)中的使用，不改变旧裁决和旧评分器字节。

本次公开[252项任务投影说明](../explorer/publication_v18/README.md)、[清洁盲解输入](../explorer/publication_v18/inputs.jsonl)、[题目与资格索引](../explorer/publication_v18/questions.public.json)、原始首答与已验收裁决。50条扩展题是252项任务中的阶段子集。标准答案、参考证明和私有完整标注包本轮未公开；内部审查使用这些资料的事实不等于网站提供了参考包下载。

评分流程将语义审查和程序聚合分开。程序检查记录、文件绑定、采样合同及统计计算；独立审查者阅读实际题面与原始作答，核对推导，主智能体（Root）验收。它不是依靠答案字符串或模型自评即可自动放行所有自然语言题目的通用裁判。

## 1. 一份作答究竟评什么

每个“题目 × 模型 × 预登记作答槽”分别产生 A、L、C 三维判定。主问题、给定正确上游的独立节点题、状态控制题分别汇总；不能把节点成绩混进主任务准确率。

|维度|代码字段|通过要求|具体检查|
|---|---|---|---|
|A：答案|`answer`|最终状态与完整目标都正确|可答／不可答等状态、实体或对象粒度、数值与单位、集合完整性、全部并列最优方案。最终答案显式错误时，后面的正确解释不能覆盖它。|
|L：推导|`logical_proof`|A通过，外显依据充分、真实且一致|支持是否来自当前材料，关系方向、条件、时间、作用域是否成立，运算与中间结论是否正确，推导是否覆盖目标。|
|C：完整输出合同|`output_contract`|A、L通过，且完成本题全部交付要求|未经修复的直接JSON和Schema、实际事实ID、要求枚举的候选路径、连续逐字引文及其一致性。C不是单纯JSON格式率。|

三维不是三个互不相关的分数。程序在[语义裁决接收函数 `adjudicated`](pass_metrics_v15/scorer.py)中拒绝“A未通过但L通过”及“A或L未通过但C通过”的裁决。A通过也不推出L或C通过。

## 2. 过程评价如何落实

过程评价使用模型实际输出的可核验依据，不把外显推导当作模型真实内部认知轨迹。审查者依照计划中预先冻结的 `rubric.criteria` 阅读原答，并与当前题面、独立求解结果和完整参考目标比较。具体流程是：

1. **核对目标。** 先明确问题要求的状态、对象与全集。批次与单件实物、完整稳定匹配全集与任意一个稳定解，不能互相替换。
2. **逐项核对支持。** 只使用该成员实际材料，确认引用对应何种事实，保留否定、条件、时间和陈述范围。别的家族成员、删前材料和外部背景知识不能补回当前缺失支持。
3. **检查推导操作。** 对关系连接、筛选、布尔重算、费用比较、容量约束、量词和全解枚举逐项核验。有限闭世界算子可通过独立枚举复算，但作者生成器自己给出的oracle不能独自充当独立真值。
4. **检查证明充分性与一致性。** 合法短证明、上下界、剪枝和替代路径可以通过；无需照抄参考路径。当前冻结规则不接受仍保留在作答中的明确错误中间操作，不能只用末尾一句正确结果抵消。
5. **单独核对输出合同。** 实际ID、连续引文和指定路径全集的错误可以只造成C失败；不能一律提升为L失败。若措辞存在真实歧义而无法确定，保留U并写出争议所在。
6. **独立审查并验收。** 裁决记录实际审查者、具体理由和输入／原答哈希，由Root验收后才进入聚合。序列化程序不能凭空生成审查事实。

上述语义工作由独立审查与Root完成。[正式裁决序列化器](../src/luna_sol_v16/finalize_grades.py)只把已经完成的审查写成绑定文件并调用冻结评分器，不是自动语言推理裁判。它还检查审查行是否缺失、重复或归属错误。审查范围必须按实际记录说明，不能把“核验另一位审查者的证据”说成又完整重读了一遍全部原答。

### 本轮真实判例

以下例子来自已验收实验的[原答与裁决公开投影](../explorer/publication_v18/results.json)，网页可在[逐题表现](https://dinghouqin.github.io/bridgeqa-zh/#/results)查看原答及理由。本轮不新增公开完整历史报告及私有标准证明附件。

|情况|A／L／C的处理|理由|
|---|---|---|
|中间把15时接续当成满足16时门槛，末尾仍给出正确22时答案|A可以P，L为F，C不能P|答案正确不消除仍存在的错误中间操作。现有202题整体有24份此类“A正确、L失败”作答，不能误说只来自142道主任务。|
|四人稳定匹配 `NEW-STABLE-challenge3` 应有3解，Luna给1解、Sol给2解|两个模型的A、L、C均为F|题目要求全部稳定解。漏解属于目标不完整，不能因已列出的解合法就通过。|
|稳定匹配 `challenge4` 先固定互为首选的一对，再穷举余下6种并给全3解|Sol的A、L、C均为P|接受成立的剪枝与短证明，不要求机械枚举全部24种。|
|新策略三段challenge，答案与策略推导正确，但首答不是合法直接JSON|Luna的A、L为P，C为F|保存未经修复的首答；JSON失败不能反过来自动否定语义正确。|
|非单调干预的动作集合选对，题目要求的费用4却写3|A为F，L和C不能P|费用也是最终目标的一部分，不能只检查动作ID。|
|`REV-08` 的“另一策略链”既可能表示错误连接，也可结合后句理解为已排除候选|L为U，A为P；独立确定的路径合同错误令C为F|真实推导争议保留复核，不能将整份作答一律改为成功或未决。|
|旧缺证题“当前确认集合”与“未知补全后的真实集合”有两种自然读法|两模型同题A均为U|题意争议不能算模型错误，也不能因碰巧符合旧engine就算成功。|

推导正确与“必须三跳／四跳”是另外两件事。短证明可能使L通过，同时推翻原来的跳数主张。当前50条扩展题全局无捷径认证为0，不能由答案或证明通过补出该认证。

## 3. P／F／U，以及两种不同的隔离

|显示|程序值|含义|
|---|---|---|
|P|`pass`|在冻结口径下有足够证据明确通过。|
|F|`fail`|有明确语义或合同错误。需要指出实际错误及证据，不能因为“看起来困难”而判失败。|
|U|`needs_review`|需【人工／强智能体复核】。题意、推导解释或合同范围暂时不能判清。U不是成功，也不是确定失败。|

**输入资格隔离**与**作答槽未决**须分开：

- 输入或gold未获资格接收时，评分器单列计划题数、待复核数和拒绝数，不进入合格题宏平均，也不算模型对或错。程序仍保留该题及已提交裁决，不能从记录中静默删除。
- 已合格预登记题中的未决裁决、缺执行槽和技术失败保留原计划槽分母。缺失或技术失败按U处理，不当语义F，也不通过补采成功答案替换。
- 同一槽可以A为P、L为U、C为F。程序保存原先提交的裁决与最终用于计分的状态，便于区分资格门禁与语义审查的影响。

## 4. pass@1、pass@5与pass^5

对同一道题、同一模型、相同有效协议，预先登记 `n` 个首次作答槽。某一评分维度明确通过 `c` 个，未决 `u` 个，明确失败 `n−c−u` 个。先逐题逐维计算，再做题宏平均；另列家族宏平均和各家族分母。

|指标|全部标签已定时的估计式|含义|
|---|---|---|
|pass@1|`c / n`|单次作答成功率的估计。另保留序号0那次首答的实际P／F／U。|
|pass@5|`1 − C(n−c,5) / C(n,5)`|从该题已登记作答中均匀无放回抽5次，至少1次成功的组合统计量；在声明的有效独立采样假设下用于估计相应能力。|
|pass^5|`C(c,5) / C(n,5)`|同样抽5次，5次全部成功的组合统计量。|

`C(a,b)`为二项式系数，`a<b`时为0。代码用整数二项式与有理数计算，返回分子、分母和小数，见[`estimate`、`metric`、`task_metrics`](pass_metrics_v15/scorer.py)。组合式的来源及原实现链接见[冻结指标说明](pass_metrics_v15/README.md)。

例如 `n=5,c=4`，三项分别为 `0.8、1、0`，最后一项不能写成 `0.8^5`。`n=10,c=5` 时，后两项分别为 `251/252` 与 `1/252`。不能把全库平均准确率代入五次公式，也不能把5道不同题当成同一道题的5次作答。

`n<5`时，两个五次指标及其界均为空，状态为 `insufficient_planned_trials`。本轮Luna／Sol每题每模型只有 `n=1`，因此全部pass@5、pass^5均为空。程序支持重复采样不等于本轮已经完成重复采样。

### 未决标签界

若有U，分别用 `c` 和 `c+u` 代入对应公式，形成“全部未决最终失败”至“全部未决最终通过”的可识别标签上下界。它描述固定队列未知标签的可能范围，**不是置信区间，也不是总体能力上下界**。

只要仍有未决，正式点估计就是空值，即使某项上下界恰好重合也不能自动改成已完成。题宏平均要求全部合格预登记题；若任何题预算不足或尚未完成裁决，不静默移除该题。完整案例补充分析可另报，但须另列自己的分母，不能替代主结果。

## 5. 两道资格门与证据绑定

### 题材资格

每题以公开输入与gold的哈希绑定资格侧表，同时登记家族、主／节点／控制分区、gold状态以及跳数主张范围。[`aggregate`](pass_metrics_v15/scorer.py)校验这些字段，不从答案文本推断跳数，不将父题证书自动传给缺证成员。

### 采样资格

请求JSON相同不足以证明远端实际有效提示完全一致，运行器可能注入额外上下文。采样资格必须由真实独立审查与Root验收，绑定实际plan、实际scored-records及非空审计证据，并明确本地入口、provider稳定性和条件IID的假设。三种决定的行为是：

|已验收的决定|正式能力点值|保留内容|
|---|---|---|
|`protocol_qualified_under_iid_assumption`|在假设及语义完成条件满足时开放|逐槽、逐题、家族及分区结果，同时标明远端独立性未被证明。|
|`fixed_cohort_only`|关闭|固定队列描述统计，不包装成总体能力估计。|
|`needs_review`|关闭|待复核状态与描述统计。|

完全缺少采样资格侧表时也只保留描述统计。若提交的侧表仍pending、未获授权审查、哈希不符或合同不合法，程序直接拒绝生成报告；不能通过把错误侧表称作“待复核”绕过校验。具体见[`sampling_gate`与`gate_official_points`](pass_metrics_v15/scorer.py)。

### 一条裁决绑定什么

裁决同时绑定 `trial_id / case_id / input_sha256 / gold_sha256 / configuration_sha256 / rubric_sha256 / response_sha256 / plan_sha256`。还须有accepted状态、至少两名不同的已注册审查者、Root批准、独立审查标记与具体理由。[`read_ref`与`adjudicated`](pass_metrics_v15/scorer.py)检查原文件及字段，不接受把旧题、另一模型或旧rubric的好分数挪来使用。

哈希只能发现文件改变、陈旧或混用，不能证明语义判断必然正确，也不能充当provider签名。审查者身份和实际阅读范围仍需通过保留的审核记录核对。

## 6. 程序执行了什么，哪些必须由审查者判断

|实现层|已实现检查|不能据此宣称|
|---|---|---|
|[`validate_plan`](pass_metrics_v15/scorer.py)|计划版本、配置／rubric哈希、各维成功标准、允许替代证明、U政策、预登记槽和同题逐字相同请求。|单有`iid_assumption=true`不能证明独立采样。|
|[`bind_completion`](pass_metrics_v15/scorer.py)|请求／响应文件SHA、当前输入、运行合同、模型别名、完成状态、首次槽；CLI入口还核对事件、进程stdout、模型／effort参数及零工具动作。|不能证明provider签名权重、所有隐藏系统消息或远端随机流独立。|
|[`aggregate`](pass_metrics_v15/scorer.py)|拒绝重复trial、复用session／原始响应文件、换入后续回答，保留未执行槽并应用资格门。|不同会话的相同答案文字可以合法出现，不能仅凭文字相同判断抄用。|
|[`adjudicated`](pass_metrics_v15/scorer.py)|接收绑定、已验收的三维裁决，执行A／L／C依赖；声称C通过时对原始文本重新直接JSON解析及Schema验证。|该函数不会自动证明引文语义支持、自然语言每步真实性或全解完备性。|
|[独立语义裁决及Root批准的公开投影](../explorer/publication_v18/results.json)|阅读原答、逐步核验、独立有限求解、接受替代证明、记录明确F和真实U。|公开投影用于查阅已接收裁决，不是完整审查过程原件。不能用程序结构通过、作者oracle或模型自评代替实际独立审查。|
|[`estimate`至`family_average`](pass_metrics_v15/scorer.py)|精确组合统计、未决界、题宏平均、家族宏平均和预算不足处理。|正确算术不自动给题目、采样协议或难度结论背书。|

原始JSON若带Markdown围栏、重复键或非标准常量，不能修复后冒充原始C通过。若已提交的“C通过”与原文JSON／Schema证据矛盾，程序报合同错误，要求复查裁决，而不是悄悄把原文修好。

## 7. 查看、校验与复算

一般阅读从[评分器网页](https://dinghouqin.github.io/bridgeqa-zh/#/scoring)和[逐题结果网页](https://dinghouqin.github.io/bridgeqa-zh/#/results)开始。逐题页的P／F／U和理由来自已经验收的裁决，不是浏览器重新调用模型判分。网站保留[公共题面及资格索引](../explorer/publication_v18/questions.public.json)，标准答案与证明包留在本地、不随本轮发布。盲解时只发送[清洁输入文件](../explorer/publication_v18/inputs.jsonl)中的单题完整对象，不能携带资格索引、参考、其他模型原答或先前审查。

本机自测入口是[评分器测试](pass_metrics_v15/test_scorer.py)：

```powershell
python -m unittest discover -s evaluation/pass_metrics_v15 -p 'test_*.py' -q
```

使用Python及`jsonschema`。在具有完整历史证据的checkout内，可以重新聚合某一批已验收记录；输出写入新的工作区路径，不改写原报告：

```powershell
python evaluation/pass_metrics_v15/scorer.py `
  --plan workspace/luna-sol-v16/runs/current_r2-gpt-6-luna/plan.json `
  --records workspace/luna-sol-v16/scored-records-r1/current_r2-gpt-6-luna.json `
  --sampling-qualification workspace/luna-sol-v16/sampling-qualifications-r1/current_r2-gpt-6-luna.json `
  --output workspace/publication-v18/recomputed-current-luna.json
```

命令引用的计划、原始证据与资格文件属于完整审计快照；下载网页JSON本身不足以重跑所有历史采样门。完整本地项目中的 `workspace/luna-sol-v16/root-final-acceptance-r1.json` 登记8份正式报告，该文件未作为公开附件上传。网站提供[公开来源与哈希清单](../explorer/publication_v18/manifest.json)、[逐槽原答及已接收裁决的公开投影](../explorer/publication_v18/results.json)，机械分析与校验实现见[分析器源码](../src/luna_sol_v16/analyze_delivery.py)。完整运行环境说明保留在本地项目，本轮不新增公开该历史README。公开摘要与逐题原答用于浏览核对；重新认证历史进程、请求和审查绑定还须取得完整证据树。

重新调用模型属于新实验，不能沿用旧回答的语义裁决。须冻结新计划、保留首次原答、重新审查实际运行与输入资格，再独立语义后审。[v15准备与执行器](pass_metrics_v15/README.md)目前仍依赖完整项目和运行环境，不是只复制三份脚本就能运行的独立软件包。格式修复、换提示、改材料、节点诊断和历史响应都不能凑成同题五次首次采样。

## 8. 当前可支持的结论

现有实现支持可追溯的三维裁决和证据绑定聚合，并允许在真实争议上保留U。它可以用于开发分析与回归评测。它不证明所有题都无捷径，不把一次错误定义为稳定高难，也没有从可见推导还原模型内部思维。模型、材料、rubric或实际运行协议变化后应冻结新版本，保留旧结果。
