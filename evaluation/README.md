# 评分器制作

本项由一人负责：把“怎样判断模型答得对不对”写成大家看得懂的规则，再做成能实际运行的评分程序。目前尚无完整评分器，代码、判分说明和人工确认的测试例子统一放在本目录。

## 先做什么

先读 [当前题库说明](../data/pilot_literature_history_v0/README.md)、[多步骤评判协议](../docs/benchmark-survey/09_多步骤评判与核心创新点回收.md) 和 [现有评分器缺口](../docs/report/2026-10-07_评分器可执行性评估.md)。从几道具体题开始，写清楚模型回答里应当有哪些内容，以及各类回答怎么判。遇到规则不清的情况，拿实际例子与两位核查人讨论。

## 必须做出的东西

- **判分说明。** 分开判断最终答案、证据、每一步操作和整条证明。讲清别名、数字、列表等答案如何比较；合法替代证明、多解、材料不足、漏步骤和格式错误如何处理。每项规则配一个能看懂的例子。
- **可运行的评分程序。** 读取题目标注和模型回答，输出逐题结果、错在哪一步及汇总成绩。说明安装和运行方法，让另一位同学能照着运行。答案碰巧正确但证据链错误，不能算整条证明成功。
- **人工确认的测试例子。** 准备32–40份有意写对或写错的回答，覆盖答案对但理由错、漏依赖、取错表格行、合法替代证明、多解和不当拒答等情况。先由人确认应该怎么判，再检查程序结果；发现不一致要修正程序或把规则讨论清楚。

判分时还要区分两种情况：上一步已经错了，导致后面跟着错；给了正确的上一步结果，这一步仍然不会做。已有 [正确上游输入的小题](../data/pilot_literature_history_v0/oracle_inputs.jsonl) 和 [对应标注](../data/pilot_literature_history_v0/oracle_gold.jsonl) 可用于后一种检查。比较原题和干扰题时，写清比较的是哪些配对、分母是多少。

## 怎样算完成

另一位同学能按说明运行程序，拿到逐题结果和汇总；上述测试例子已经由人核对，误判已修正或明确列为待解决问题；[实测与难度整理负责人](../model-testing/README.md)能用同一套规则处理真实模型回答。评分器完成与否以这些交付为准。
