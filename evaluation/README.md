# 评分器制作

2026-10-27更新：[完整指标与过程评价说明](SCORING_GUIDE.md)解释A／L／C、P／F／U、资格门、证据绑定、逐题重复采样统计及真实判例；可从[在线评分器](https://dinghouqin.github.io/bridgeqa-zh/#/scoring)和[Luna／Sol逐题结果](https://dinghouqin.github.io/bridgeqa-zh/#/results)阅读。[本轮公开投影](../explorer/publication_v18/README.md)提供252项清洁输入与审阅索引，其中50项为扩展阶段；标准答案与证明包本轮未公开，原答及裁决理由保留。现有代码负责接收真实独立裁决并精确聚合，不是无需语义审核的自动放行器。本轮每题每模型仅1次首答，五次指标留空。

本项目负责把“怎样判断模型答得对不对”写成可核对的规则与可运行程序。当前已有[证据绑定的pass评分器v15](pass_metrics_v15/README.md)，适配现有合成题库，提供答案、逻辑证明、输出合同三维的pass@1、pass@5、pass^5，配独立审查、Root验收、题材与采样资格门。遇疑保留复核；它不是通用自动语义裁判。实际逐跳审查与模型集成验证见[本轮报告](../QA_Generator/validation/2026-10-27_逐跳捷径审查与pass指标评分器.md)。

## 历史来源题的衔接

历史来源题从[首轮题库说明](../data/pilot_literature_history_v0/README.md)、[多步骤评判协议](../docs/benchmark-survey/09_多步骤评判与核心创新点回收.md)和[早期评分器缺口](../docs/report/2026-10-07_评分器可执行性评估.md)衔接。它们不能直接套用v15合成算子的gold；须先登记各自输入资格和独立语义裁决。以下要求继续适用。

## 必须做出的东西

- **判分说明。** 分开判断最终答案、证据、每一步操作和整条证明。讲清别名、数字、列表等答案如何比较；合法替代证明、多解、材料不足、漏步骤和格式错误如何处理。每项规则配一个能看懂的例子。
- **可运行的评分程序。** 读取题目标注和模型回答，输出逐题结果、错在哪一步及汇总成绩。说明安装和运行方法，让另一位同学能照着运行。答案碰巧正确但证据链错误，不能算整条证明成功。

判分时还要区分两种情况：上一步已经错了，导致后面跟着错；给了正确的上一步结果，这一步仍然不会做。已有 [正确上游输入的小题](../data/pilot_literature_history_v0/oracle_inputs.jsonl) 和 [对应标注](../data/pilot_literature_history_v0/oracle_gold.jsonl) 可用于后一种检查。比较原题和干扰题时，写清比较的是哪些配对、分母是多少。

## 怎样算完成

另一位同学能按说明运行程序，拿到逐题结果和汇总；[实测与难度整理负责人](../model-testing/README.md)能用同一套规则处理真实模型回答。评分器完成与否以这些交付为准。
